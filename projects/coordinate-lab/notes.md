## 0. 本周要建立的三个认知

| # | 认知 | 为什么重要 |
| --- | --- | --- |
| 1 | **4326 是球面经纬度，3857 是平面米制**，两者之间的换算不是简单的"乘个系数" | 决定你该用哪个 CRS、什么时候必须换 |
| 2 | **Web 墨卡托在非赤道地区会系统性放大**，放大系数 = `1/cos(纬度)` | 这是"量出来的距离不对"的根因，也是 W10 空间分析结果失真的来源 |
| 3 | **"图层对不上底图"只有三类原因**，可以逐一定位 | 把玄学变成排查流程（验收标准第 2 项） |

## 1. 实验一：同一份数据在 4326 / 3857 下的长度差异

### 1.1 准备数据

素材文件 `w1_test_features.geojson` 里有三条线，每条都故意设计成对某个结论：

| 线 | 位置 | 几何 | 真实长度（椭球量算） | 3857 下量出的长度 | 膨胀 |
| --- | --- | --- | --- | --- | --- |
| **A** | 广州 23.13°N，113°E→114°E | 东西向，1 度经度 | 103,319 m | 111,319 m | **+7.7%** |
| **B** | 广州 23°N→24°N，113.26°E | 南北向，1 度纬度 | 110,574 m | 121,389 m | **+9.8%** |
| **C** | 北纬 60°→61°，20°E | 南北向，1 度纬度 | 111,412 m | 226,085 m | **+103%** |

> 理论放大系数是 `1/cos(纬度)`：
> - 23.13°N → `1/cos(23.13°)` = **1.0874**（+8.7%）
> - 60.5°N → `1/cos(60.5°)` = **2.0308**（+103%）
>
> A/B 与理论值的小差异来自椭球（WGS84）与墨卡托（正球）的模型不同——这本身就是个可以写进笔记的细节。

### 1.2 操作步骤

1. 打开 QGIS，`图层 → 添加图层 → 添加矢量图层`，选 `w1_test_features.geojson`。
   该文件声明为 CRS84（等价于 EPSG:4326），QGIS 会自动识别。
2. **确认工程的坐标参考系**：`工程 → 属性 → 坐标参考系`，设为 **EPSG:4326**。
3. 打开测量工具：`视图 → 面板 → 测量`，或工具栏的尺子按钮。
4. **关键设置**：在测量面板上，把"测量"选项切到 **椭球**（Ellipsoidal），单位选 **米**。
   - 若选"平面"（Cartesian），量出的会是 4326 下的"度数×系数"，没有物理意义。
   - 这一步就是验收标准里"结果和 QGIS 一致（误差 < 1 米）"的前提。
5. 依次量三条线，记录长度到下表。
6. **然后把工程 CRS 改成 EPSG:3857**（`工程 → 属性 → 坐标参考系`），**重复测量**。
   - 注意：改工程 CRS 只是"显示/计算时用的平面"，数据本身仍是 4326。
   - 此时测量工具的"平面"选项才有意义。
7. 填入对比表：

| 线 | 4326 椭球量算 (m) | 3857 平面量算 (m) | 比值 | 是否接近 1/cos(纬度) |
| --- | --- | --- | --- | --- |
| A | | | | |
| B | | | | |
| C | | | | |

### 1.3 要得出的结论

- 3857 的量算结果**只在地球赤道附近准确**；
- 变形量随纬度升高而**急剧增大**（60°N 直接翻倍）；
- 所以在 3857 下做面积/距离统计（W10 的缓冲区、服务区覆盖）**必须警惕**；
- 需要精确量算时 → 用 4326 + 椭球，或换投影坐标系（如 CGCS2000 高斯克吕格 `EPSG:4547` 等）。

> ⚠️ 工程上常见错误：在 3857 下算"某小区 500 米内有多少个学校"。在广州会多算约 8.7%，到哈尔滨（45°N）会多算约 41%。这是你要在 W10 避开的坑。

## 2. 实验二：高德坐标 vs WGS84 的偏移量

### 2.1 生成两个点

运行脚本打印出两组点：

```bat
conda activate webgis
python w1_proj.py points
```

输出会给你两段 CSV 内容。分别存成：
- `points_wgs84.csv`（GPS 原始坐标）
- `points_gcj02.csv`（高德/腾讯火星坐标）

### 2.2 在 QGIS 里叠加

1. `图层 → 添加图层 → 添加分隔文本图层`，选 `points_wgs84.csv`：
   - 文件格式：CSV
   - 几何定义：点坐标，X 字段 = `lon`，Y 字段 = `lat`
   - 几何 CRS：**EPSG:4326**
2. 同样导入 `points_gcj02.csv`，CRS 也选 **EPSG:4326**。
3. 给两个图层设置明显不同的符号（一个红、一个蓝）。
4. **放大到最大级别**，用测量工具量两点的距离。
5. 换成 3857 工程 CRS 再量一次，对比。

### 2.3 预期结果

广州塔附近的两点应相差约 **500～600 米**（具体值以脚本输出为准，脚本会打印每个城市的偏移量）。

### 2.4 要得出的结论

| 结论 | 说明 |
| --- | --- |
| 偏移量**随位置变化** | 不是固定值，所以**不能**用一个常量去减 |
| 偏移量级 **100～700 米** | 在 z=18 的底图上肉眼非常明显 |
| 偏移**是非线性的** | 必须用算法转换（脚本里的 `wgs84_to_gcj02`），不能线性平移 |
| 合规提醒 | 不要拿高德/百度瓦片直接上线商用；底图用天地图等合规来源并注意审图号 |

> 脚本里附带了 `gcj02_to_wgs84`（迭代反算）和往返误差验证，可以自己看精度。

## 3. 验收标准第 2 项：「图层对不上底图」的三类原因

这是本周最值钱的一页。**任何"对不上"的问题，先按这三类排查，不要瞎试。**

### 类别一：CRS 定义错误（数据"身份"错）

数据**实际**是什么坐标系，和它**声明**的是什么坐标系不一致。

**典型表现**：
- 点和底图整体**平移**几百米（错位，但形状正常）→ 多半是 GCJ-02 被当成 WGS84
- 数据跑到**地球另一边**或**南极附近** → 声明成了 3857 但实际是 4326（或反之）
- 数据在**原点附近**（0,0）→ 度的数值被当成了米

**排查方法**：
1. 看 QGIS 图层属性里的 CRS 声明值
2. 把鼠标移到一个已知地物上，读状态栏的经纬度坐标
3. 与地图上实际位置对比：
   - 读出来是 113.26, 23.12 这种**度数**，但显示位置偏出几百米 → GCJ-02/WGS84 混淆
   - 读出来是 12610000, 2640000 这种**大数**，但声明是 4326 → 实际是 3857

**修法**：`图层 → 属性 → 源`，改 CRS 定义（是"改定义"而不是"重投影"，两者结果不同，见 3.4）

### 类别二：缺少 .prj 文件 / 元数据缺失

**Shapefile 特有**（GeoJSON 没这个问题，因为它把 CRS 写在文件里）。

**典型表现**：QGIS 提示"该图层没有坐标参考系"，并让你手选。

**排查方法**：看 `.shp` 同目录下有没有 `.prj` 文件。

**修法**：手动指定正确的 CRS；或从数据来源方索取 `.prj`。

### 类别三：动态投影（OTF）设置问题

QGIS 默认开启"即时重投影（On-the-fly reprojection）"，会自动把不同 CRS 的图层转到工程 CRS 显示。

**典型表现**：
- 关掉了 OTF → 不同 CRS 的图层无法同时正确显示
- 工程 CRS 设错 → 所有图层一起偏
- 单个图层 CRS 设错 → 只有该图层偏

**排查方法**：
1. 确认 `工程 → 属性 → 坐标参考系` 是合理的（一般 4326 或 3857）
2. 确认右下角坐标显示用的是工程 CRS
3. 逐个图层检查 CRS 声明

### 3.4 补充：改定义 vs 重投影（超级常见的混淆）

| 操作 | 含义 | 什么时候用 | QGIS 位置 |
| --- | --- | --- | --- |
| **改定义（Set CRS）** | 只改"标签"，不动坐标数值 | 数据实际是 A，但被错误标成 B | 图层属性 → 源 → 分配 CRS |
| **重投影（Reproject）** | 真正计算新坐标数值，生成新文件 | 数据要换到另一个坐标系使用 | `矢量 → 数据管理工具 → 重投影图层` |

**搞错后果**：该重投影的时候改了定义 → 数据位置完全错乱；该改定义的时候重投影了 → 错上加错（把错的数值又算了一遍）。

## 4. Python 与 QGIS 的一致性验证（验收标准第 3 项）

验收要求"投影换算脚本能跑，结果和 QGIS 一致（误差 < 1 米）"。这样做：

```bat
conda activate webgis
python w1_proj.py project
```

记下输出的 3857 坐标，然后在 QGIS 里验证：

1. 新建一个临时点图层（`图层 → 创建图层 → 新建临时暂存图层`，几何类型选点，CRS 选 3857）
2. 手动输入脚本算出的 x, y 作为坐标添加点
3. 把该点与底图（或与 w1_test_features.geojson 的某个端点）对比，应完全重合
4. 或者反向：在 QGIS 里用"识别要素"读取某点的 3857 坐标，与脚本输出比对

**误差来源提示**：如果差了几十米甚至几百米，通常不是算法问题，而是：
- QGIS 用的 PROJ 版本与 conda 的 pyproj 版本对应的 EPSG 定义不一致（极少见）
- 你比对的两个点本来就不是同一个点
- GCJ-02 干扰（如果数据来自高德）
