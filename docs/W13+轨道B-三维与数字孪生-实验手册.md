## 0. 本轨道要建立的三个认知

| # | 认知 | 为什么重要 |
| --- | --- | --- |
| 1 | **三维地图同样是"瓦片树 + 按需调度"，不是把整个场景塞进显存** | 3D Tiles 的瓦片根节点和 W3 的 z/x/y 金字塔是同一种数据结构：一棵树，按"这块在屏幕上够不够精细"（屏幕空间误差）决定加载哪一层。有这个迁移，几十 GB 的倾斜摄影能跑在浏览器里就不神秘了 |
| 2 | **坐标系在三维里是第一坑，且多了一个维度：椭球面坐标 vs 地心直角坐标** | 二维里错位是"平移几百米"，三维里错的是"模型插到地里 / 飞到天上 / 整体偏转"。Cesium 内部用**地心空间直角坐标（笛卡尔）+ 弧度制**，和你熟的经纬度（角度制）是两套语言，中间隔着一次 17 参数转换 |
| 3 | **entity 和 3D Tiles 是两种数据组织哲学：贴海报 vs 摆乐高** | entity 是"一个对象一张海报"：几千个以内随便用，十万个就卡死；3D Tiles 是"预先装好乐高盒、按视距决定倒哪几块"：百万级对象的唯一解。选错组织方式，后面所有性能优化都是白干 |

## 2. 学（穿插在每周前半段，总计约 12~15 小时）

### 2.1 CesiumJS 从零：Viewer 八大控件与两大 Provider（3 h）

**学完你能做什么**：从零跑通"注册 Ion → 拿 token → Vite 脚手架 → 蓝色地球"全流程；能说出 Viewer 每个控件的生产取舍；能给国内 XYZ/WMTS 源选对 tilingScheme。

**CesiumJS 四件套**：
- **定义**：一个开源的三维地球渲染库——你在网页里创建一个 `Viewer` 对象，它给你一颗能转、能缩、能贴图的地球。
- **类比**：OpenLayers 是二维画板，Cesium 是三维画板 + 自带一个地球仪。
- **最小示例**：见下方"上手流程化"第 6 步的 12 行代码。
- **常见误区**：① 以为它是 three.js 的插件——它自带完整场景管理，与 three.js 平级；② 以为必须注册 Ion 才能用——Ion 只是官方数据托管服务，底图/地形都可以换别家（P1）；③ 以为 `npm i cesium` 后直接 import 就能跑——静态资源必须单独拷贝（练习 1，P3）。

**上手流程化（注册 ion → 蓝色地球，7 步）**：

1. **注册 Ion 账号**：打开 <https://ion.cesium.com/> → Sign up（GitHub 账号可直登）。免费档额度学习足够。
   - **失败分支**：页面打不开/加载卡死 → 先查 Steam++ hosts 加速状态（[week01.md 第六节](../notes/week01.md)：Steam++ 不运行时它劫持的域名指向 127.0.0.1 即不通），启动 Watt Toolkit 或临时关 hosts 加速。
2. **拿 token**：登录后进 <https://ion.cesium.com/tokens>，复制 `Default Token`（一长串 eyJ 开头字符）。写进项目 `.env`：`VITE_ION_TOKEN=eyJ...`（**.env 不进 Git**，W6/W11 的老规矩）。
3. **建脚手架**（运行位置：PowerShell，`projects/` 目录）：

```powershell
npm create vite@latest cesium-lab -- --template vanilla
cd cesium-lab
npm i cesium
```

   > **预期输出**：vite 模板生成成功提示 + `added xx packages`。
   > **失败时**：报 `Cannot find package 'rolldown'` → 你用了 pnpm，删了用 npm 重来（W0 坑 #1，P4）。
4. **静态资源拷贝 + Vite 配置**：Cesium 带一堆静态资源（Workers 多线程脚本、Widgets 样式与图片），Vite 不会自动搬。两条路线选一条：
   - 省事路线：`npm i vite-plugin-cesium`，`vite.config.js` 里 `plugins: [cesium()]`（插件自动处理资源拷贝与环境变量）；
   - 手动路线（推荐走完一次，真正理解）：在入口 JS 顶部设 `window.CESIUM_BASE_URL = '/cesium/'`，把 `node_modules/cesium/Build/Cesium/` 下的 `Workers`、`Assets`、`ThirdParty`、`Widgets` 四个目录 **copy 到 `public/cesium/` 对应位置**，并 `import 'cesium/Build/Cesium/Widgets/widgets.css'`。
5. **写第一个 Viewer**（`main.js` 全文）：

```js
import * as Cesium from 'cesium'
import 'cesium/Build/Cesium/Widgets/widgets.css'
window.CESIUM_BASE_URL = '/cesium/'            // 手动路线必需；用插件可删
Cesium.Ion.defaultAccessToken = import.meta.env.VITE_ION_TOKEN

const viewer = new Cesium.Viewer('app', {
  animation: false, timeline: false,            // 非时序项目关掉时钟与时间轴
  baseLayerPicker: false,                       // 底图自己在代码里指定
})
viewer.camera.flyTo({                            // 飞到广州上空看 5 秒
  destination: Cesium.Cartesian3.fromDegrees(113.2644, 23.1291, 50000),
})
```

   同时 `index.html` 里给容器明确尺寸：`<div id="app" style="height:100vh"></div>`（高度为 0 是静默白屏，P6）。
6. **跑起来**（运行位置：PowerShell，`cesium-lab/` 目录）：

```powershell
npm run dev
```

   > **预期输出**：`Local: http://localhost:5173/`；浏览器打开看到**蓝色地球**，拖动丝滑，5 秒后飞到广州上空；Console 无 `CESIUM_BASE_URL` 报错、无 404 的 `Workers/*.js`。
   > **失败时**：白屏 + Console 报 `Cannot find module './Workers/...'` → P3，第 4 步资源没拷贝对；页面出现但 Geocoder/地形空白 → token 没生效，检查 `.env` 变量名必须是 `VITE_` 开头且改完要重启 dev server。
7. **提交 Git 前**：`.gitignore` 加 `node_modules/`、`public/cesium/`（4 个拷贝目录几十 MB，不进仓库，README 写一行"npm run setup:cesium 生成"的脚本说明）。

`new Cesium.Viewer('app')` 默认给你八个控件，逐个认脸（在自己页面上关一遍再开一遍）：

| 控件 | 干什么 | 生产环境常见做法 |
| --- | --- | --- |
| Animation | 时间动画时钟（播放历史/预报轨迹） | `animation: false` 关掉 |
| Timeline | 底部时间轴 | 非时序项目 `timeline: false` |
| Geocoder | 顶部地址搜索框（背后是 Cesium Ion 的在线服务） | 关掉，换成自己的地名服务 |
| HomeButton | 回到初始视角 | 保留 |
| SceneModePicker | 3D / 2D / 三维地图（Columbus View）切换 | 保留，二三维联动时它就是开关 |
| BaseLayerPicker | 底图/地形切换面板 | **通常关掉**，自己在代码里指定 Provider |
| NavigationHelpButton | 右下角"怎么操作地球"帮助 | 看习惯后关掉 |
| SelectionIndicator | 选中实体时的高亮圈 | 联动高亮会自己实现，可关 |

**两个 Provider 四件套**：
- **定义**：`ImageryProvider` 决定每个 z/x/y 瓦片从哪个 URL 取图；`TerrainProvider` 决定地表起伏数据从哪来。
- **类比**：`ImageryProvider` = 地球的"壁纸供应商"；`TerrainProvider` = 地球的"起伏供应商"。
- **最小示例**：

```js
viewer.imageryLayers.addImageryProvider(new Cesium.UrlTemplateImageryProvider({
  url: 'https://basemaps.cartocdn.com/light_all/{z}/{x}/{y}.png',
  tilingScheme: new Cesium.WebMercatorTilingScheme(),   // 3857 网格源必须显式指定
}))
```

- **常见误区**：接国内 XYZ/WMTS 源时报错位/拉伸，九成是"源是墨卡托网格、Provider 默认按经纬度直切"。关键差异在 **tilingScheme（瓦片切分方案）**：`GeographicTilingScheme`（按经纬度直切，z 级全球 `2^(z+1) × 2^z`）与 `WebMercatorTilingScheme`（你 W3 熟悉的 3857 方形网格贴成球面展开）。Cesium 内置 `UrlTemplateImageryProvider`（万能 XYZ 模板）、`WebMapTileServiceImageryProvider`（OGC WMTS）、`SingleTileImageryProvider`（单张贴图）。地形默认是 `EllipsoidTerrainProvider`——一个光滑椭球，山是平的；换 `CesiumWorldTerrain`（Ion 在线）或自建 `CesiumTerrainProvider`（quantized-mesh 格式）后，模型才能"贴"在真实山坡上而不是悬空/入地。

**entity vs 3D Tiles（核心认知 3，"贴海报 vs 摆乐高"）**：
- **entity**：每个对象（点、 polyline、label、model）都是一个独立"海报"，Cesium 每帧都要挨个检查、贴一次。贴 3000 张没问题，贴 50 万张浏览器直接趴窝。优点是**随时改**（换色、挪位、加属性、点击选中天然支持）。
- **3D Tiles**：把海量对象预先切成一棵瓦片树（乐高盒分层装箱），运行时按"这盒在屏幕上误差超阈值没"决定开箱还是用大的顶替。优点是**能装百万级**，缺点是改起来费劲（数据是预烘焙的）。
- 选型口径：业务矢量（你的点线面、几千个以内）→ entity；倾斜摄影/激光点云/BIM 大模型 → 3D Tiles；两者混用是常态。

### 2.2 坐标系：三维第一坑（3 h，本轨道最重要的一节）

**学完你能做什么**：能手写 `fromDegrees → cartographicToCartesian` 翻译链；能走一遍"三维版四方交叉验证"并解释四份结果为什么必须一致。

**Cesium 内部的"母语"四件套**：
- **定义**：地心空间直角坐标（Cartesian，米）+ **弧度制**。右手系：**x 轴指向赤道与本初子午线交点，y 轴指向赤道东经 90°，z 轴指北极**。
- **类比**：经纬度是"地球表面上的地址"（东经多少度、北纬多少度）；笛卡尔坐标是"把地球当一块豆腐，地心当原点，报一个 (x, y, z) 空间位置"。
- **最小示例**：

```js
// 浏览器 Console（cesium-lab 页面开着时）：
const c = Cesium.Cartographic.fromDegrees(113.2644, 23.1291, 0)   // 度 → 弧度 Cartographic
const xyz = Cesium.Ellipsoid.WGS84.cartographicToCartesian(c)     // 弧度 → 笛卡尔米
console.log(xyz.x, xyz.y, xyz.z)   // ≈ -2325107, 5387254, 2495890
// 反方向：cartesianToCartographic 返回的仍是弧度，要 Cesium.Math.toDegrees 转回来
```

- **常见误区**：**忘转弧度是新手第一大症状**：把 113.26 当弧度传进去，模型直接跑到地球另一面；其次是经纬顺序（Cesium 一律 lon 在前）和高度轴 z（默认 0 = 椭球面，不是地面）。

**"17 参数转换"是什么（大白话）**：两个大地基准之间换算，主流是布尔莎（Bursa–Wagna）路线——**7 个参数**：3 平移 + 3 旋转 + 1 尺度；扩展版把旋转/平移参数分置在两个原点（14 参数），再加上**随时间的速率项**（板块运动每年厘米级）凑成 15/17 参数口径。学习期你基本不会手填它（Cesium 只认 WGS84/4978），但必须知道它存在：**北京 54 / 西安 80 等历史成果与 CGCS2000/WGS84 不是同一个基准，参数用错就是几米到上百米的系统性偏差**——这种错"修不好"，因为它随位置变化而不是固定平移（呼应 W1 的 GCJ-02 结论：367~724 m、非线性）。为什么三维里更危险：二维错位是"平移几百米"肉眼可辨；三维里基准错了表现为**整个场景绕地心某轴转了个微小角度**——近处差几米、远处差几十米，高程一起错，看上去像"模型自己歪了"。

**三个 EPSG 在 Cesium 里的位置**（承接 W1 的四方交叉验证方法论，[week01.md 十四节](../notes/week01.md)）：

| 代码 | 是什么 | 在 Cesium 里的角色 |
| --- | --- | --- |
| EPSG:4978 | WGS84 **地心直角坐标**（米） | 就是 Cesium 内部母语的数字表达（Cesium 内部量纲是米、逻辑上是弧度笛卡尔）。PostGIS 里 `ST_Transform(geom, 4978)` 出来的 x/y/z 可以直接喂 `new Cesium.Cartesian3(x, y, z)` |
| EPSG:4326 / 4490 | 经纬度（度，椭球面坐标） | 通过 `fromDegrees` 进入 Cesium。**国内正式成果是 4490（CGCS2000）**，W1 结论 3 说过 4326/4490 椭球参数差在小数第 8 位，普通三维可视化尺度下可直接当 4326 用——但要写进口径说明 |
| EPSG:3857 | Web 墨卡托（米，投影面坐标） | **Cesium 没有它的位置**。它是二维瓦片世界的方言；矢量进 Cesium 前必须还原成经纬度（`ol/proj` 的 `toLonLat` 或 pyproj）。只有 3857 网格的 XYZ 瓦片源，用 `UrlTemplateImageryProvider` 时显式指定 `tilingScheme: new Cesium.WebMercatorTilingScheme()`，别让默认的经纬度直切去猜 |

**三维版四方交叉验证（逐步操作，取广州 113.2644, 23.1291, 0）**：

1. **pyproj 版**（运行位置：Anaconda Prompt）：

```powershell
conda activate webgis
python -c "from pyproj import Transformer; t=Transformer.from_crs(4326,4978,always_xy=True); print(t.transform(113.2644,23.1291,0))"
```

   > **预期输出**：一行三元组，形如 `(-2325107.x, 5387254.x, 2495890.x)`（米）。
   > **失败时**：报 `ModuleNotFoundError: pyproj` → 没激活 webgis 环境；结果两个分量符号与下表相反 → 漏了 `always_xy=True`，经纬顺序被当 lat/lon 了。

2. **PostGIS 版**（运行位置：PowerShell 任意目录）：

```powershell
docker exec -it pgis psql -U postgres -c "SELECT ST_AsText(ST_Transform(ST_Force3D(ST_GeomFromText('POINT(113.2644 23.1291)',4326),0),4978));"
```

   > **预期输出**：`POINT Z (-2325107.x 5387254.x 2495890.x)`，与第 1 步一致。
   > **失败时**：报 `cannot find srid 4978` → 你的 PostGIS 版本 spatial_ref_sys 缺该条（极少见），先 `SELECT srid FROM spatial_ref_sys WHERE srid=4978;` 确认。

3. **Cesium 版**：cesium-lab 页面 F12 Console 粘上面"最小示例"那三行。
   > **预期输出**：与前两步的 x/y/z 一致（米级，小数后不同只是精度显示）。
4. **QGIS 版**：新建临时 scratch 点图层放一个广州点 → 工程右下角 CRS 切成 `EPSG:4978` → 用"识别要素"或顶点编辑器读该点坐标。
   > **预期输出**：坐标读数与前三方一致。
   > **失败时**：读数仍是度 → 工程 CRS 没切成功，看右下角是否真显示 EPSG:4978（N11 坑同款：切完查状态栏）。

四方数值应当一致（W1 已证明这类转换是封闭公式）——对不上就是你自己某处漏了度/弧度或高度。**这个动作做一遍，三维坐标系的玄学就祛魅了。**

### 2.3 3D Tiles 原理：一棵按屏幕空间误差裁剪的树（2.5 h）

**学完你能做什么**：打开一份 `tileset.json` 读出根节点包围球与 geometricError；能用"和 W3 瓦片金字塔哪里同、哪里不同"讲清 LOD 调度。

- **定义**：3D Tiles 是把三维场景预切成一棵树形瓦片结构的开放格式；每个节点带包围体 + 几何误差，运行时按屏幕空间误差（SSE）决定展开还是停。
- **类比**：W3 学的二维瓦片金字塔是"按缩放级别 z 切格子"；3D Tiles 也是一棵金字塔树，但切的是**任意三维几何**，而且不再按固定层级——按"这一盒内容投到屏幕上，误差超过几个像素就换更精细的子盒"。
- **最小示例**：官方 Sample 3D Tiles 的 `tileset.json`（练习 4 会打开读）：`root.boundingVolume`（根包围球）、`root.geometricError`（根误差）、`root.children[].content.uri`（子节点指向哪个 `.b3dm`/`.gltf`）。
- **常见误区**：以为 SSE 是固定的——它是"几何误差 ÷ 相机距离 ÷ 视口参数"每帧现算的投影量，所以同一瓦片远看用粗盒、近看展开。调度器每帧沿树下降：误差够小就停（用当前盒），误差大就展开子盒继续问。
- 呼应 W3 认知 1：二维地图是"一堆 `<img>` 按 z/x/y 贴出来"，三维场景是"一堆瓦片盒按树形加载进来"。**变的是瓦片形状（不再是正方形格子）和调度依据（z 级 → SSE），不变的是"金字塔 + 按需 + 缓存"三件套。** 面试能讲清这个同构关系，是轨道 B 验收项"讲清 LOD 与瓦片调度"的核心素材。
- **b3dm vs gltf**：`.b3dm`（Batched 3D Model）是"一堆小模型打包成一盒 + 一张属性批量表（batch table）"，旧世代格式，倾斜摄影转换器常产它，能携带逐对象属性——在成片模型里点中某一栋楼并读出它的名字，靠的就是 batch table；`.gltf`/`.glb` 是"三维界的 JPEG"（开放标准、单体模型、带 PBR 材质），新一代 1.1 规范直接用它当瓦片内容。**现状：拿到什么用什么，新做 BIM/精模尽量产 gltf。**

### 2.4 倾斜摄影：OSGB → 3D Tiles（2 h + 练习 4）

**学完你能做什么**：讲清倾斜摄影"为什么真、为什么笨"；选一个工具把一份小样 OSGB 转成 3D Tiles 并记录命令与耗时。

- **定义**：几架无人机朝五个方向（下、前、后、左、右）同时拍照，事后软件"空三"匹配重建出一个**贴图精美但没有结构**的大模型。
- **类比**：一张巨型立体照片，不像乐高——一栋楼在数据里是"一堆三角面 + 照片纹理"，不是"一堵墙、一个屋顶"的对象。
- **工具链简述（国内主流口径）**：原始交付常是 **OSGB**（SuperMap/ContextCapture 系常用的开放场景二进制树）。转换路线：`OSGB → 3D Tiles`，常见选择有 **CesiumJS 官方老的 3D Tiles 1.0 转换链**、**Square Simulators 的 osgb-3dtiles（开源命令行）**、**大疆 DaaS / TiandD 系列**、**SuperMap iDesktop 导出**。本手册不指定唯一解，选一个能跑通你样片的即可（练习 4），把转换参数与耗时记录进笔记。
- **为什么单个瓦片几百 MB**：倾斜摄影是"照片级纹理"，一个瓦片内可能塞了几十万三角面 + 4K 级纹理图；瓦片切分器默认追求"少切"以减少请求数，切片参数（如最大瓦片大小、纹理压缩 ktx2）不激进时，单盒几百 MB 很常见。对策：转换时限制 tile size、开纹理压缩、只保留视区范围（裁剪外圈废数据）、上 CDN。
- **局限（必须写进 README）**：① 精度——平面几十厘米但立面/细长物（电线杆、栏杆）常拉毛、悬空；② **语义缺失**——模型里"这栋楼"不是一个对象，是一堆无名三角面，height/用途/权属属性全靠外挂或人工单体化；③ 更新周期长、量大、坐标系常带本地假设（回到 §2.2 的坑）。
- **常见误区**：以为倾斜模型可以像矢量一样点哪改哪——它是烘焙死的"照片"，改一栋楼意味着重飞重算。

### 2.5 二三维联动：消息总线思路（2 h + 练习 5）

**学完你能做什么**：用一根 10 行的消息总线让 OL 和 Cesium 互不 import 地完成双向联动；能背出事件名约定表。

- **定义**：消息总线 = 一个谁都能发、谁都能听的事件转发器；两个地图库不直接互调 API（耦合死），都在总线上喊话。
- **类比**：公司大群，各部门（地图）不私聊，都在群里喊话，谁相关谁响应。
- **最小代码骨架**（照抄可用，`bus.js` 约 10 行）：

```js
const bus = new EventTarget()
export const emit = (msg) => bus.dispatchEvent(new CustomEvent(msg.type, { detail: msg }))
export const on = (type, fn) => bus.addEventListener(type, (e) => fn(e.detail))
```

- **事件名约定表**（写进 README，字段照抄可用）：

| 事件名 | 方向 | 必备字段 | 说明 |
| --- | --- | --- | --- |
| `feature:selected` | 二维→三维 | `featureId`、`geometry`（GeoJSON，**EPSG:4326 角度制**）、`style` | 点二维要素，三维 flyTo 并高亮；`height` 为 null 时三维端 clampToGround |
| `view:changed` | 三维→二维 | `center{lon,lat}`、`height`、`heading`、`pitch`、`ts` | 三维视角变化二维跟飞；**必须节流 200~300 ms**（P7） |
| `layer:visibility` | 双向 | `layerId`、`visible` | 图层开关联动 |
| `error:raised` | 任一侧 | `source`、`message` | 一侧出错另一侧兜底提示 |

- **常见误区**：① 让 OL 代码里直接 `import Cesium` 互相调——升级任何一边都炸；② 消息里混用坐标系——**约定写死：所有总线消息坐标一律 EPSG:4326 角度制，谁消费谁转换**（Cesium 端收消息第一件事 `Cartographic.fromDegrees`），这是"两套地图坐标系方言"和平共处的唯一低成本方案。

### 2.6 性能：帧率、requestRenderMode 与调度开关（1.5 h）

**学完你能做什么**：用 DevTools Performance 面板录一段拖动并读出主线程/GPU 帧耗时；能说清每个调度开关防的是什么。

- **帧率怎么测（先有尺子再谈优化）**，两条路都做一遍：
  1. **自测 fps 计**：Cesium `viewer.clock.onTick` 每帧触发，自己打时间戳算每秒帧数（每秒汇总一次即可，别在 onTick 里算除法刷屏）。
  2. **DevTools Performance 面板（逐步）**：F12 → 顶栏 `Performance` → 左上角红点 ● Record → 回到页面**匀速拖动地球 10 秒** → 点 Stop → 等解析 → 看三条：① 顶部 `Frames` 行的绿/红条（红条=掉帧，悬停看 fps）；② `Main` 泳道的黄色 JS 长块（脚本耗时）；③ 底部 Summary 的 `Rendering/Painting` 占比（GPU 侧）。导出：右键 Save profile 存档对比。
- **基线口径**：静态场景 ≥ 50 fps、倾斜摄影拖动 ≥ 25~30 fps 算可接受，低于 20 fps 用户就会觉得"卡"。把 W9 的"性能要有自己测出来的数字"纪律延续过来。
- `requestRenderMode: true`：默认 Cesium 每帧无脑重画（60 fps 空转）；打开后**只在场景真的变了才重画**——CPU/风扇救星，静态可视化必开。代价：自己驱动的动画（自定义插值）要手动 `viewer.scene.requestRender()` 触发一帧，否则"不动了"（P8）。
- `cullRequestsWhileMoving: true`（默认开）：快速拖动/飞行时**不发**新瓦片请求，停下才加载——防止"越拖越卡、请求堆积"。`cullRequestsWhileMovingMultiplier` 调阈值；如果客户抱怨"停下后半天才出模型"，就是这里和 `maximumMemoryUsage` 的权衡。
- 其他常调项：`viewer.scene.globe.maximumScreenSpaceError`（越大越糊越快）、3D Tiles `tileset.maximumScreenSpaceError`（同上）、`scene.maximumMemoryUsage`（MB 预算）、entity 数量阈值（>1 万就该考虑上 3D Tiles 或 `PointPrimitives` / `BillboardCollection` 这类"批量原语"，即手写乐高）。
- **常见误区**：在 requestRenderMode 下用 fps 评省电效果——此时"帧率低"恰恰是省电，要用 CPU 占用评这组（P8）。
- 排错入口永远是 F12 → Network 看瓦片请求、Console 看 `An error occurred while rendering`（WebGL 上下文丢失——页面挂太多 WebGL 实例或显存爆）。

## 5. 坑预告（按你的真实环境定制，遇到回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | Cesium Ion 需要注册 token | 页面报 `ION access is not available` / World Terrain 和 Geocoder 空白 | 去 ion.cesium.com 注册免费账号取 token，`Cesium.Ion.defaultAccessToken = import.meta.env.VITE_ION_TOKEN` 走 `.env`（W6 的路子）；**学习期也可以全程不用 Ion**：地形换非 Ion 的 quantized-mesh 源或椭球，底图用天地图——不是所有功能都要 Ion |
| P2 | 国内影像服务的瓦片网格口径 | 天地图影像铺在球面上被拉伸、南北错位（不是偏移几百米——天地图基准是 4490≈WGS84，**没有** GCJ 偏移） | 天地图 `img_w`/`mat_w` 是 4490 **经纬度直切**瓦片，Provider 要用 `GeographicTilingScheme` 口径（WMTS Provider 配 EPSG:4490 瓦片方案）；阿里/ArcGIS 系 XYZ 是 3857 墨卡托网格，配 `WebMercatorTilingScheme`。选错 tilingScheme 就是拉伸/错位。真正的 GCJ 偏移只来自高德/腾讯数据，那种要在数据侧纠偏，Cesium 修不了 |
| P3 | npm 装完 cesium 直接 import 就白屏 | Console 报 `Cannot find module './Workers/...'` 或 404 `Widgets/widgets.css`；页面全黑 | §3 练习 1 的手动路线：`CESIUM_BASE_URL` + 把 `Build/Cesium` 下 Workers/Assets/ThirdParty/Widgets 拷进 `public/cesium/`。Vite 不会自动帮你搬这些——这是 Cesium+Vite 的第一大坑 |
| P4 | pnpm / junction 布局复发 | Worker 路径解析失败、拷贝脚本找不到目录 | W0 坑 #1 的延伸：**轨道 B 全程用 npm**，且 `vite-plugin-cesium` 版本与 vite 主版本要匹配（`npm ls vite cesium` 先对版本再装） |
| P5 | Ion/GitHub 上的样例 tileset 时通时断 | `tileset.json` 请求超时、`net::ERR_CONNECTION_RESET` | [week01.md 第六节](../notes/week01.md) 老朋友：Steam++ hosts 加速里 `github.com`/`raw.githubusercontent.com` 指向 127.0.0.1，**它不运行就不通**；启动 Watt Toolkit 或临时关 hosts 加速。Ion 域名同理优先排查代理状态 |
| P6 | Viewer 容器高度为 0 | 地球不出现但 Console 无报错 | CSS 上 `#app { height: 100vh }`；双视口 flex 布局里给明确高度。经验：Cesium 的错不一定在 Console，"渲染区域尺寸为 0"就是静默白屏 |
| P7 | 联动跟飞把页面拖死 | Cesium 每帧发 `view:changed`，OL 每帧 animate，双向风暴、帧率 < 10 | 总线上加节流（200~300 ms）+ 取消旧动画；"三维驱动二维"默认**停稳再同步**（呼应 cullRequestsWhileMoving 的哲学） |
| P8 | `requestRenderMode: true` 后动画不动 | 自定义动画卡住、点了不刷新 | 该模式下必须主动 `viewer.scene.requestRender()`；或把动画交给 `viewer.dataSources/clock` 驱动的通道。测 fps 时注意：requestRenderMode 下"帧率低"可能恰恰是**省电**，用 CPU 占用而不是 fps 评这组 |
| P9 | OSGB 转换出的模型整体悬空/入地 | tileset 加载后位置对但贴不进地形，或整体高差明显 | 检查 transform 里烘焙的高程基准：1985 国家高程（正高）≠ 椭球高，两者差**大地水准面差距 N，全国约 -10 ~ -55 m**；转换器把哪种当 height 要问交付方。排错顺序：先切 `EllipsoidTerrainProvider` 排除地形干扰，再对已知点用练习 2 的方法量高差 |
