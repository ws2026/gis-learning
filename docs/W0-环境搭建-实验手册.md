# W0 实验手册：环境搭建

> 对应《WebGIS 12 周学习计划》W0。建议时间：**开课前 3~5 天**（每天 1.5~2 h，共约 6~8 h），不必占掉正式周。
> 环境前提：Windows 10/11 一台能联网的电脑，C 盘剩余 ≥ 30 GB，最好有 D 盘放 Docker 数据；管理员权限（开 WSL2 要用）。
> 承接说明：这是整条链路的第一块砖。W0 只做一件事——**让工具都"能被验证"**。装完不等于装好，每条安装命令后面都跟着一条验证命令，跑通再走下一步。
> 通关后你的状态应该等于 [notes/week01.md](../notes/week01.md) 里记录的那份环境：Node + Git + VS Code + QGIS + Docker PostGIS（容器名 `pgis`）+ conda `webgis` 环境。

## 0. 本周要建立的三个认知

| # | 认知 | 为什么重要 |
| --- | --- | --- |
| 1 | **开发环境是"一堆各自独立的运行时"，不是一个整体** | Node、Python、Git、Docker、QGIS 各管一摊。报错先问"这是谁家的错"，而不是"我的电脑坏了"——90% 的报错归属很清楚 |
| 2 | **Docker 里的 PostGIS 是"别人电脑上的一个数据库程序"，你只是开了个门牌号** | `-p 5432:5432` 把容器内的端口映射到本机。理解这个，你就明白为什么容器里能 `psql` 而本机连不上（端口没映射 / 容器没起） |
| 3 | **网页上的地图 = 一堆按 `z/x/y` 编号的小图片** | 瓦片就像把世界切成一个个 256×256 像素的方块拼图，`z` 是"切成几块"的档位，`x/y` 是第几块。W0 只要在 Network 面板里亲眼看到这些编号在变，就成功了 |

## 1. 学：把六件工具装上，每件都要"当场验证"

> 通用原则：**下载一律走官网**；安装路径**纯英文、无空格**（推荐 `D:\xx\` 系列，本仓库笔记里的路径都是这个风格）；装一个验证一个，不要一口气全装完再排查。

### 1.1 安装清单与验证命令（对照着打勾）

> **学完你能做什么**：能把六件工具各自装好并用一条验证命令证明"装好了"（而不是"点了安装包"）；装完任何一件，你能说出它的版本号是在哪个终端里跑出来的。

| 工具 | 装哪个 | 安装要点 | 验证命令 | 在哪个工具里运行 | 预期看到 |
| --- | --- | --- | --- | --- | --- |
| Node.js | LTS 版（当前 22.x） | 一路下一步，**不要**手改安装路径里的默认 Program Files 以外的位置；自带 npm | `node -v` / `npm -v` | PowerShell | `v22.x.x`、`10.x.x` |
| Git | for Windows 最新 | 默认编辑器选 VS Code：`git config --global core.editor "code --wait"`；行尾选 `Checkout as-is, commit Unix-style` | `git --version` | PowerShell | `git version 2.x` |
| VS Code | 最新版 | 装扩展：中文（可选）、Prettier；命令行 `code` 要能用（安装时默认已加入 PATH） | `code -v` | PowerShell | 版本号 |
| QGIS | **LTR 3.44.15**（长期支持版） | 用 OSGeo4W 网络安装包（Online Installer），勾 QGIS LTR + 默认组件；它自带 **OSGeo4W Shell**，里面有 `ogr2ogr`，W2 直接能用 | `QGIS → 帮助 → 关于` | QGIS 图形界面 | `3.44.x`，并记下版本号 |
| Docker Desktop | 最新 | **先开 WSL2 再装**；设置里改 `Resources → Storage → Disk image location` 到 D 盘，**必须在第一次 `docker pull` 之前改**，否则镜像还在 C 盘 | `docker version` / `docker info` | PowerShell | Client+Server 两个版本块 |
| Miniconda | 最新（Python 3.12 系） | 安装时**不要勾** "Add to PATH"（正确做法，避免污染 node/git）；装完用开始菜单的 **Anaconda Prompt** | `conda --version` | Anaconda Prompt | `conda 26.x` |

打开 WSL2（**管理员 PowerShell**：开始菜单搜 PowerShell → 右键 → 以管理员身份运行，之后重启电脑）：

```powershell
wsl --install
wsl --update
wsl --version        # 期望看到 WSL 版本 >= 2.x，内核版本非空
```

- **预期输出**：`wsl --version` 打印三行以上（`WSL 版本: 2.x.x`、`内核版本: 5.15.x`、`Windows 版本: 10.0.x`）。
- **失败时**：`wsl --install` 报"请启用虚拟机平台" → BIOS 里没开虚拟化（VT-x），重启进 BIOS 打开；或命令不存在 → Windows 太旧，先跑 Windows Update。

> **WSL2 是什么（大白话）**：Windows 里塞了一个轻量 Linux。Docker Desktop 靠它来跑 Linux 容器——你可以理解成"在自家客厅支了个帐篷，帐篷里是另一套操作系统"。
> **常见误区**：① 以为装了 Docker Desktop 就不用管 WSL2——Docker 的 Linux 容器全靠它；② `wsl --install` 后没重启就装 Docker，必报错；③ 以为 WSL 会吃掉很多内存——它按需分配，闲着不占。

### 1.2 Python 环境：建 `webgis` 环境（conda 26.x 有合规门槛）

> **学完你能做什么**：能独立建出一个叫 `webgis` 的隔离 Python 环境，激活它，并用一行命令证明 pyproj/geopandas/shapely 都装好了；知道为什么平时要用 Anaconda Prompt 而不是普通 PowerShell。

在 **Anaconda Prompt**（开始菜单搜这个名字，别用普通 PowerShell——Miniconda 故意没加 PATH，见坑 P9）里：

```bat
:: 第 1 步：先接受频道服务条款，否则 conda create 会直接报 CondaToSNonInteractiveError
:: （week01.md 坑 N1/N7，三条都要执行）
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/main
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/r
conda tos accept --override-channels --channel https://repo.anaconda.com/pkgs/msys2

:: 第 2 步：用仓库里现成的环境定义文件建环境（推荐，版本可复现）
cd /d D:\xx\GitProjects\gis-learning
conda env create -f webgis-env.yml

:: 第 3 步：激活并验证
conda activate webgis
python -c "import pyproj, geopandas, shapely; print(pyproj.__version__, geopandas.__version__)"
```

预期：打印 `3.8.0 1.2.0`（pyproj 3.8.0 / geopandas 1.2.0 / shapely 2.2.0）。

每条命令的"预期输出 / 失败时"：

| 命令 | 预期输出（成功长这样） | 失败时（最常见报错及含义） |
| --- | --- | --- |
| `conda tos accept ...`（三条） | 静默成功，回到提示符 | `CondaToSNonInteractiveError` 没消失 → 三条漏了某条，逐个补 |
| `conda env create -f webgis-env.yml` | 滚屏下载后末尾 `done`，提示 `conda activate webgis` | `CondaToSNonInteractiveError` → 上一步没做（坑 P8）；下载超时 → 网络问题，重跑一次（conda 会续传） |
| `conda activate webgis` | 提示符前面多出 `(webgis)` | `'conda' 不是内部或外部命令` → 你不在 Anaconda Prompt 里（坑 P9/N2） |
| `python -c "import pyproj, ..."` | 打印 `3.8.0 1.2.0` | `ModuleNotFoundError` → 环境没激活成功，看提示符有没有 `(webgis)`；`python` 闪退/跳商店 → 坑 P9 的别名没关 |

> **conda 环境是什么（类比）**：像给每门课准备一个独立的文具盒。`webgis` 这个盒子里的 Python 包互不干扰别的项目，坏了直接换个盒子，不用重装整个系统。

顺手做两件小事（week01.md 已记录）：

```bat
:: 关掉微软商店的 python 空壳（否则输入 python 会闪退或提示去商店）—— 见坑 P9
:: 设置 → 应用 → 高级应用设置 → 应用执行别名 → 关闭 python.exe / python3.exe

:: 导出环境定义，写进笔记当基线
conda env export --no-builds > webgis-env-lock.yml
```

### 1.3 逐参数拆解：Docker 起 PostGIS（本周重头戏）

> **学完你能做什么**：能默写出起 PostGIS 容器的完整命令，每个参数都能讲清"不写会怎样"；容器起不来时知道先看 `docker ps -a` 还是 `docker logs pgis`。

主计划给的命令，**每个参数都要能说清**（【PowerShell】运行，先确认 Docker Desktop 已启动——系统托盘有鲸鱼图标）：

```powershell
docker run --name pgis -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgis/postgis:16-3.4
```

| 参数 | 大白话 | 类比 | 写错的后果 |
| --- | --- | --- | --- |
| `docker run` | 用一个镜像"开一家新店" | 镜像是加盟手册，容器是开起来的那家店 | 和 `docker start` 混淆：店开过就用 `docker start pgis`，别重复 `run`（同名会冲突） |
| `--name pgis` | 给容器起个固定门牌号 | 以后 `docker start pgis` / `docker logs pgis` 全用它 | 不写就是随机名字，后面每次都要查 `docker ps` |
| `-e POSTGRES_PASSWORD=postgres` | 环境变量：数据库超管密码 | 门上贴的"钥匙是这把" | 漏了直接报错：`Database is uninitialized and superuser password is not specified` |
| `-p 5432:5432` | 端口映射，**左边是我家（Windows），右边是店里（容器）** | 把店里柜台的对讲机接到你桌上 | 漏了 → 容器里 `psql` 能连、你在 PowerShell 连不上；写 `127.0.0.1:5432:5432` 更安全（只听本机） |
| `-d` | 后台运行（detached），别占着窗口 | 让店自己营业，你走人 | 漏了 → 关窗口 = 停服务，重启电脑后要 `docker start pgis` |
| `postgis/postgis:16-3.4` | 镜像名 `:` 版本号 = PostgreSQL 16 + PostGIS 3.4 | 指定加盟品牌 + 手册版本 | 只写 `postgis/postgis` 会拉最新版，教程步骤可能对不上 |

**国内网络拉不动镜像**（week01.md 坑 #5：`registry-1.docker.io` 被 DNS 污染解析到 Facebook 网段）。解法：Docker Desktop → Settings → Docker Engine，加入镜像加速后 **Apply & restart**：

```json
{
  "registry-mirrors": [
    "https://docker.m.daocloud.io",
    "https://docker.1ms.run"
  ]
}
```

验证镜像源生效（注意坑 #6：值在下一行缩进里，`grep` 要带 `-A3`）：

```powershell
docker info | Select-String -Pattern "Registry Mirrors" -Context 0,3
```

- **预期输出**：匹配行下面跟着两行缩进的 `https://docker.m.daocloud.io/`、`https://docker.1ms.run/`。
- **失败时**：只看到 `Registry Mirrors:` 后面没东西 → 加速器没生效，回 Docker Engine 配置检查 JSON 有没有语法错误（多余逗号最常见），改完**必须** `Apply & restart`。

### 1.4 天地图 key（可选但强烈建议，10 分钟）

> **学完你能做什么**：能独立申请到一个天地图浏览器端 key，填进 `.env` 并让底图列表出现"天地图·矢量"；能说清为什么学习阶段就该用天地图而不是高德。

**为什么**：高德/百度瓦片是 GCJ-02 加密坐标且不允许商用直连；**天地图用 CGCS2000（接近 WGS84）、有审图号、可合规上线**，后面 W1/W3/W6 都要用它当对照底图。

**怎么做**（浏览器 + 编辑器）：

1. 到 <https://console.tianditu.gov.cn/> 注册，`创建新应用` → 应用类型选 **浏览器端**；
2. 在项目里 `复制 .env.example 为 .env`（VS Code 左侧文件树右键 → 复制 → 重命名），填入：

   ```
   VITE_TIANDITU_KEY=你的key
   ```

   ⚠️ 教程里的占位符**必须替换**——`你的key` 这种字样直接粘上去 100% 失败，而且报错很隐晦（底图静默不出）。
3. 回到终端 **重启** `npm run dev`（`.env` 改动不会热更新，Ctrl+C 停掉再 `npm run dev`）；
4. 到控制台把开发地址加进 **referer 白名单**：加 `127.0.0.1` 和 `localhost`，否则返回 403。

**预期看到**：底图列表多出「天地图·矢量」「天地图·影像」两项，点上去能正常出图。

## 2. 练：四个练习，每个都有明确验收点

### 练习 1：跑通 webgis-starter（周初，约 1 h）

**为什么做**：验证 Node + 包管理器 + 编辑器三件套同时可用，并且第一次看到"活的" WebGIS 页面。

**前置检查**：

- [ ] `node -v` 和 `npm -v` 在【PowerShell】里有版本号输出（没有 → 回 §1.1 装 Node）
- [ ] 仓库已 clone 到 `D:\xx\GitProjects\gis-learning`，且 VS Code 能打开它
- [ ] 记住纪律：**只用 npm，不用 pnpm**（坑 P1）

**怎么做**：

1. VS Code → 顶部菜单 `终端 → 新建终端` 打开集成终端（默认就是 **PowerShell**，先别换 Git Bash，少一个变量）。
   - 预期现象：窗口下方出现终端面板，提示符是 `PS D:\xx\GitProjects\gis-learning>`。
   - 失败分支：没出现终端 → 快捷键 Ctrl+`（反引号，Tab 键上面那个）再试。
2. 进项目、装依赖、起服务（【PowerShell】）：

   ```powershell
   cd D:\xx\GitProjects\gis-learning\projects\webgis-starter
   npm install
   npm run dev
   ```

   - 预期：`npm install` 滚屏后末尾无红色 `npm error`；`npm run dev` 出现 `VITE vX.X.X  ready in XXX ms` 和 `Local: http://127.0.0.1:5173/`。
   - 失败分支：`npm error` 提到网络/超时 → 换个时间重跑或换 npm 镜像；`Cannot find package 'rolldown'` → 你之前用 pnpm 装过（坑 P1），删掉 `node_modules` 后用 `npm install` 重装。
3. 浏览器打开 <http://127.0.0.1:5173>（用 Chrome 或 Edge）。
   - 预期现象：左边地图、右边控制面板，默认 OSM 底图。
   - 失败分支：页面打不开 → 终端里的 dev server 是不是被 Ctrl+C 停了；端口被占 → 看 `vite.config.js` 里 `port: 5173`。
4. 逐个操作一遍：把底图**全部点一遍**（不配天地图 key 时面板里有 5 个：OSM、Carto 浅、Carto 深、Esri 影像、OpenTopoMap；
   按 1.4 节配好 key 后多出天地图矢量与影像，共 7 个——主计划说的"六个底图"指的就是这一组可切换底图）、
   勾选/取消三个示例图层、点一个要素看弹窗、
   用绘制工具画一个点和一个面、测一次距离、把一个 GeoJSON 文件从资源管理器**拖进页面**
   （可以拖 [public/data/sample-points.geojson](../projects/webgis-starter/public/data/sample-points.geojson)）。
   - 预期现象：每个操作都有对应画面变化；拖入文件后地图自动飞到数据位置。
   - 失败分支：天地图两项不出图 → key 没配或 referer 白名单没加 `127.0.0.1`（§1.4）；拖拽无反应 → 扩展名必须是 `.geojson`/`.json`。

**完成自查**：

- [ ] 页面打开、底图能切换、示例点线面能显示（这就是主计划验收项 1），截图存进笔记
- [ ] 7 个底图（或没配 key 时 5 个）全部点过一遍，每个都出图
- [ ] 绘制点/面、测距、拖拽导入都亲手做过
- [ ] 终端保持 `npm run dev` 运行时页面才能开——你理解了两者的关系（关掉终端页面就死）

> ⚠️ **只用 npm，别用 pnpm**（week01.md 坑 #1）：pnpm 的 junction 软链布局会让本机报
> `Cannot find package 'rolldown'`。starter 的 [README.md](../projects/webgis-starter/README.md) 里写的是 `pnpm install`，
> 照抄会失败——所有 `pnpm xxx` 一律替换成 `npm xxx`（`pnpm dev` → `npm run dev`）。

### 练习 3：Network 面板初体验（周中，约 1 h，本周最有画面感）

**为什么做**：把"地图库的魔法"变成"看得见的 HTTP 请求"。这是 W3 的地基，现在只需要会看，不需要会解释全部。

**前置检查**：

- [ ] `npm run dev` 正在跑，<http://127.0.0.1:5173> 页面能打开
- [ ] 浏览器是 Chrome 或 Edge（F12 的界面才和下面描述一致）

**怎么做**（全程【浏览器 DevTools→Network】）：

1. 保持页面开着。按 **F12** 打开 DevTools → 切到 **Network**（网络）标签。
   - 预期现象：右侧（或下方）出现一个空表格，顶部有过滤框和一排类型按钮（All / Fetch / Img …）。

4. **拖动地图**：看新瓦片请求集中在**新露出的边缘**，已经看过的地方不再请求。
5. **滚轮放大一级**：请求数量明显变多；观察 URL 里中间那个数字（`z`）从 10 → 11 → 12 的跳变。

### 练习 4：Docker 起 PostGIS 并连上（周末前完成，约 1.5 h）

**为什么做**：W7 整周要用它，现在先证明"门牌号能打开、钥匙能开门"。

**前置检查**：

- [ ] Docker Desktop 已启动（系统托盘有鲸鱼图标，图标静止不动才算就绪；在转圈是还在启动）
- [ ] 镜像加速器已配置且 `Apply & restart` 过（§1.3，否则 pull 会超时，坑 P3）
- [ ] 磁盘镜像位置已挪到 D 盘（**必须**在第一次 pull 之前，坑 P2）

**怎么做**（【PowerShell】，逐条抄，每条的预期/失败见注释和下文）：

```powershell
# 1) 确保 Docker Desktop 在跑（系统托盘有鲸鱼图标），然后拉镜像 + 起容器
docker pull postgis/postgis:16-3.4
docker run --name pgis -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgis/postgis:16-3.4

# 2) 看它活着
docker ps                       # STATUS 应为 Up xx seconds
docker logs pgis                # 末尾应出现 "database system is ready to accept connections"

# 3) 进容器里连一次（不用装 psql！）
docker exec -it pgis psql -U postgres
#    进去之后依次输入：
#    \pset pager off      ← 关掉分页器，否则长输出会卡在 END（week01.md 坑 #7）
#    SELECT version();
#    CREATE EXTENSION IF NOT EXISTS postgis;
#    SELECT PostGIS_Version();
#    \q                   ← 退出

# 4) 证明"门牌号（端口）"是通的：这条在容器内部执行，不依赖本机装没装 psql
docker exec -it pgis psql -h localhost -U postgres -c "SELECT version();"

# 5) 主计划验收项 2 这条语句，要在本机装了 psql 客户端时才跑得动
#    （psql 随 PostgreSQL 安装器一起装；没装就用下面的 QGIS 图形界面连，效果等价）
psql -h localhost -U postgres -c "SELECT version();"
```

逐条的预期与失败分支：

| 步 | 预期现象 | 失败分支 |
| --- | --- | --- |
| 1 pull | 各层进度条走完，`Status: Downloaded newer image` | `connectex 超时` → 坑 P3，加速器没配/没重启 Docker |
| 1 run | 打印一串 64 位容器 ID | `name is already in use` → 之前建过同名容器：`docker rm -f pgis` 后重来，或直接 `docker start pgis` |
| 2 ps | `pgis` 行 STATUS = `Up xx seconds` | 列表空 → `docker ps -a` 看是不是 Exited，是则 `docker logs pgis` 找原因（多半是密码参数漏了） |
| 2 logs | 末尾 `ready to accept connections` | 停在 `initdb` 或报错 → 照报错搜，八成是数据目录残留，`docker rm -f pgis` 重 run |
| 3 psql | 提示符变 `postgres=#`，`SELECT PostGIS_Version();` 返回 `3.4.x` | 卡在 `END` → 按 `q`，然后 `\pset pager off`（坑 P6） |
| 4 | 返回一行 `PostgreSQL 16.x ...` | 必然通过；不通过说明第 2 步就没活 |
| 5 | 返回版本行 | `'psql' 不是内部或外部命令` → 本机没装客户端，**不是数据库的错**，用 QGIS 连（见下）验收 |

**完成自查**：

- [ ] `psql -h localhost -U postgres -c "SELECT version();"` 能连上并返回结果（或 QGIS 连接测试成功）
- [ ] `docker ps` 里 `pgis` 状态 Up，`docker logs pgis` 末尾有 ready 字样（截图）
- [ ] `SELECT PostGIS_Version();` 返回 `3.4.x`（截图）
- [ ] 实际做过一次"重启电脑 → `docker start pgis` → 重新连上"的完整循环
- [ ] QGIS `数据源管理器 → PostgreSQL → 新建` 测试连接通过

第 4) 步在容器里执行必然通过（说明数据库服务和端口映射都正常）；第 5) 步若提示"无法识别 psql"，
不是数据库的问题，是你本机没装客户端——用 QGIS 连同一个库验收即可。

> 参考 [week01.md 第五节命令备忘](../notes/week01.md)：`docker start pgis`（重启电脑后要手动起）、`docker exec -it pgis psql -U postgres`、`docker logs pgis`。
> 顺便把 QGIS 连库走一遍：`数据源管理器 → PostgreSQL → 新建`，主机 `localhost`、端口 `5432`、数据库 `postgres`、用户 `postgres` → `测试连接`。

## 4. 坑预告（按你的真实环境定制，遇到就回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | 照 README 用了 pnpm | `Cannot find package 'rolldown'`，`npm run dev` 起不来 | **一律用 npm**（week01.md 坑 #1，pnpm 的 junction 软链布局与 Node ESM 解析冲突）。`pnpm install` → `npm install`，`pnpm dev` → `npm run dev` |
| P2 | 先 `docker pull` 后改存储位置 | C 盘被镜像吃掉，D 盘空着干瞪眼 | 设置 `Disk image location` 必须在第一次 pull **之前**改；改完 `Apply & restart`，再删旧镜像重新拉 |
| P3 | 没配镜像加速器就拉 `postgis/postgis` | `dialing registry-1.docker.io:443 ... connectex` 超时 | DNS 污染（week01.md 坑 #5）。Settings → Docker Engine 加 `registry-mirrors`，Apply & restart；别反复重试同一条 pull |
| P4 | `docker info` 查不到镜像地址 | 明明配了，输出里看不到 | 值在**下一行的缩进**里（坑 #6）：`docker info \| Select-String "Registry Mirrors" -Context 0,3` 或 `grep -A3` |
| P5 | 重启电脑后连库失败 | `connection refused` / QGIS 报连不上 | Docker Desktop 没自启 → 容器没起。`docker ps -a` 看状态，`docker start pgis`；起不来就 `docker logs pgis` |
| P6 | psql 里输入没反应，底部显示 `END` | 触发了 `less` 分页器（坑 #7） | 按 `q` 退出，然后 `\pset pager off` 永久关闭 |
| P7 | GitHub / `raw.githubusercontent.com` 突然打不开 | 网页打不开、示例数据下载失败 | 你的 hosts 里有 **Steam++（Watt Toolkit）** 的加速记录，把这批域名指到 `127.0.0.1`，**只有它运行时才通**（week01.md 第六节）。启动它，或在它界面里关掉 hosts 加速（会自动还原）。`git push` 走 SSH:443 不受影响——**clone 别人的仓库优先用 SSH 地址** |
| P8 | `conda create` 报 `CondaToSNonInteractiveError` | 环境建不起来，提示 Terms of Service 未接受 | conda 26.x 新增合规校验（N1/N7）：`defaults`、`r`、`msys2` 三个频道**逐条** `conda tos accept` |
| P9 | 输入 `python` 没反应/闪退 | 指向 0 字节的 `WindowsApps\python.exe` 空壳 | 「设置 → 应用 → 应用执行别名」关掉 `python.exe` / `python3.exe`（N5）；日常用 **Anaconda Prompt**，因为 Miniconda 故意没加 PATH（N2） |
| P10 | PowerShell 里 Python 输出中文乱码 | 脚本明明没错，汉字成 `???` 或乱码 | PS 5.1 控制台编码问题（N3）：`chcp 65001` + `[Console]::OutputEncoding=[Text.Encoding]::UTF8`，或设 `PYTHONIOENCODING=utf-8`；文件本身没事，别急着改代码 |
| P11 | QGIS 首次启动报 `vw_srs already exists` | `Update of view in private qgis.db failed` | 首次初始化 bug（N8）：备份后删除 `%APPDATA%\QGIS\QGIS3\profiles\default\qgis.db`，重启自动重建（它只存系统元数据，不含你的项目数据） |
| P12 | Git Bash 里 `cd D:\xx\...` 失败 | `No such file or directory` | Git Bash 把 `\` 当转义符（坑 #8）：用 `/d/xx/...` 或 `"D:/xx/..."` |
| P13 | 笔记里 Markdown 标题变灰、不生效 | 一整段变成代码底色 | 有 ``` 代码块**没闭合**（坑 #9）。补一行顶格的三个反引号；小心中文输入法打出的全角引号 |
