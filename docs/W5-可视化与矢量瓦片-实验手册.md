## 0. 本周要建立的三个认知

| # | 认知 | 为什么重要 |
| --- | --- | --- |
| 1 | **专题图不是"画得好看"，是"选了一种说法"**：分级方法（等间隔/分位数/自然断点/标准差）+ 色带类型（顺序/发散/类别）决定了读者会不会得出错误结论 | 同一组数据，等间隔分 5 级可能显示"东强西弱"，分位数分 5 级显示"均匀分布"。这是 GIS 专业的核心手艺，也是面试"你怎么做专题图"的标准答案框架 |
| 2 | **聚类和热力图都在"用视觉代替数字"**，而且各自骗人的方向不同：聚类数字受**聚合半径**与缩放级别强影响（同一份数据，radius 40px 显示 8 个点、radius 100px 显示 2 个点）；热力图色带是**相对密度**，会把 1% 和 5% 的差别涂成红与蓝，人眼读成"差很多" | 不懂这点的人会拿图做决策。"能说出它怎么骗人"是本周验收项 2，也是你区别于"会调库的人"的地方 |
| 3 | **矢量瓦片 = 把数据切成披萨：每块自带几何（能算能变样式），但不带样式（没有颜色、没有字体、没有你数据的字段全集）** | 一句话同时解释了三件事：为什么换配色不用重新切片、为什么一块披萨上的数据能变粗变细但不能变出没带进来的字段、以及为什么 MVT 上"点击取属性"要么靠 `queryRenderedFeatures` 要么得回后端。这是 W9 性能路线的地基 |

## 1. 学（约 4 小时，周一到周二）

### 1.1 专题图三件套之一：分级配色（Choropleth，1 h）

> **学完你能做什么**：拿到一组数值，先画文字方图看分布，再说出"该用哪种分级方法和色带、读者会怎么误读"；并在 `viz-lab` 里用 `makeChoroplethStyle` + `breaks.js` 把分级图画对。

**定义一句话**：给"面"按数值大小分档涂深浅，就是 choropleth（中文常叫分级设色图/等值域图）。**类比**：把 11 个区的数值当成分学习小组——等间隔=按固定分数段划（分都挤在 85~95 时有的组空着）；分位数=保证每组人数一样（把 95 和 96 硬拆两组）；自然断点=按成绩天然断层分；标准差=按"高于/低于平均分多少"分。
**大白话**：三个决定要分开做：**分几级、怎么切、用什么颜色**，顺序别反——先看数据分布（下面 10 秒方图）再决定怎么切，切完再配颜色。分级方法的取舍（每种适合什么分布、会被怎样误读）全在这张决策表里：

| 分级方法 | 怎么切 | 适合的分布长相（方图特征） | 配套色带 | 会骗人的地方 |
| --- | --- | --- | --- | --- |
| 等间隔（Equal interval） | (max−min)/n | 均匀铺满、读者需要"刻度直觉" | 顺序 | 值扎堆时 4 级空着、1 级挤满 —— 图上大片同色，看不出差异 |
| 分位数（Quantile） | 每级要素数一样 | 单调长尾、关心"谁排前面"（要素 <20 个时分级很抖） | 顺序 | 隐含"每级一样多"的错觉，绝对差距被抹平；90 分和 89 分同色、和 91 分反而不同组 |
| 自然断点（Jenks） | 让组内差异最小、组间最大 | 成堆 + 堆间有缝；国内 GDP、人口常这样 | 顺序 | 断点是算法算的，读者以为是业务标准线（图例必须写"自然断点"）；别人复现你的边界可能有微小差 |
| 标准差 | 以均值 ±kσ 切 | 近似对称、想表达"高于/低于平均" | 发散（中点 = 均值） | 数据偏态（长尾）时均值不代表典型值 → 大多数区都"低于平均" |
| 手动断点 | 业务口径（如"≥30% 为达标"） | 有政策/标准线的场景 | 顺序或发散 | 忘了在图例里写明"线从哪来"，读者会以为是你随手分的 |

**选方法前先看数据长什么样**。在浏览器里 10 秒画一个文字方图【浏览器 DevTools→Console】：

```js
const vs = gis.ctx.dataLayers.get('districts').layer.getSource().getFeatures()
  .map(f => f.get('fake_pop')).filter(v => v != null).sort((a, b) => a - b);
for (const [lo, hi] of [[0,200],[200,400],[400,600],[600,800],[800,1000]])
  console.log(String(lo).padStart(4), '▓'.repeat(vs.filter(v => v >= lo && v < hi).length));
```

预期输出（条子长短 = 每个数值区间里有几个区；广州各区人口密度的真实形态大概长这样，模拟值同理）：

```
   0 ▓                       <- 1 个区，很低
 200 ▓▓▓▓                    <- 2 个区
 400 ▓▓▓▓▓▓▓                 <- 3 个区（450~480 挨在一起：这就是"断点"）
 600 ▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓▓         <- 6 个区挤在这一带
 800 ▓                       <- 1 个 outlier（天河）
```

读法：这种"成堆 + 缝隙 + 孤点"的形状 → 选**自然断点**；若 600 那一排均匀铺满无堆叠 → **等间隔**才不吃亏。失败时：条子全空 → 字段名拼错或还没跑练习 1 的数据准备（`fake_pop` 不存在时 `get()` 返回 undefined，被 filter 光）。

**色带三型（务必和分级方法配套）**：
- **顺序（Sequential）**：单色由浅到深，适合"从小到大"的连续量（人口密度）。色盲安全首选 viridis 系、单色蓝/橙。
- **发散（Diverging）**：中间一个中性色 + 两端各一色，**必须有意义 midpoint**（均值、0、标准线）。适合"高于/低于平均"。
- **类别（Categorical / Qualitative）**：颜色只做身份证，不排序。适合用地类型、行政区代码。⚠️ 类别色**超过 7~8 种读者就记不住**，必须靠图例一一对照；红绿配对要避开（约 8% 男性色弱）。

**硬性制图要求（练习 3 会检查）**：分级边界数值写进图例（"12.5 ~ 25.0"而不是"第 2 档"）；单位写上；类别图例按业务顺序排而不是按出现顺序。
**OpenLayers 里怎么实现**：不要手写 5 个 `if`。两条路，都要会用：

```js
// 路线 A：一个 style 函数 + 一个查表（数据量小、级数固定时最直观）
import {Fill, Stroke, Style} from 'ol/style.js';

export function makeChoroplethStyle(breaks /* number[] */, colors /* string[] */, field) {
  return function style(feature) {
    const v = feature.get(field);
    // TODO: 二分或线性找出 v 落在哪一级（找不到时返回"无数据"灰色样式）
    const idx = /* ... */;
    return new Style({
      fill: new Fill({color: colors[idx]}),
      stroke: new Stroke({color: 'rgba(255,255,255,0.85)', width: 1}), // 白边是分级图的命
    });
  };
}
```

路线 B：`ol/style` 的 `Style[]` + filter（OL 会用每个 Style 的 filter 逐要素匹配）。好处：不用每次 `new Style`（OL 每帧对每个要素调用样式函数，这是真的 CPU 开销）。

W4 遗留的坑在这里会兑现：`styles.js` 里 `whiteHalo()` 的思路（描边防压盖）在分级图上对应**行政边界白边**——没有它，相邻同色图斑会糊成一片，读者以为是一个区。

**常见误区**：① 没看分布就默认"分位数 5 级"（工具默认值不是决策）；② 左闭右开写法不统一，边界值掉级（坑 P1）；③ 把 `null` 当最小值落进最低档（坑 P3）；④ 涂人口**总数**而非密度——面积大的区天然"显得重要"（面权偏差）。

### 1.2 三件套之二、之三：分类配色 + 图例（0.6 h）

> **学完你能做什么**：用一行查表代码给类别字段上色，知道"全部落灰色"先查键类型；并能判断一张图例是否"正确"（数值、单位、无数据档、联动四件事都亲手验证过）。

**定义一句话 + 类比**：分类配色 = 值到颜色的一一映射，颜色只是身份证，不含大小——像给每个社团发不同颜色腕带，红色不代表"比蓝色强"，只是"我是轮滑社的"。
- **分类配色**：实现就是"查表"：`COLOR_BY_TYPE.get(feature.get('type')) ?? FALLBACK`。注意键的类型（`'01'` vs `1`，`adcode` 从 JSON 里可能是字符串），这是最常见的"全部落到 fallback 灰色"的原因。**最小可运行示例（先猜再敲）**【浏览器 DevTools→Console】：`new Map([['440103','#2563eb']]).get(440103) ?? 'gray'` —— 猜返回什么？是 `'gray'`！键是字符串、传数字查不到；`get('440103')` 才出颜色。
- **图例**：本周坚持用 **HTML + CSS** 自己画，不用 `ol/legend` 之类现成控件。理由：**图例的正确性必须被你亲手验证一次**（数值、色块、单位、"无数据"项、和图层开关联动），用组件会把这 5 个考点全替你藏起来。以后接 GeoServer 时 `GetLegendGraphic` 才是自动路线（W8 会用到，本周先埋钩子）。可直接复制的完整代码见练习 3。
- **联动语义**：图层关掉 → 图例整块灰掉或隐藏（两种都要知道，默认选"整块变灰并显示删除线"，因为它保留位置、不跳动）。
- **常见误区**：① 图例数字手抄，图层改了分级忘了改图例（必须从同一个 `breaks` 变量渲染）；② 透明度滑条只作用于图层、图例不变淡，颜色比图上深；③ 类别图例按数据出现顺序排，读者找不到规律。

### 1.3 Cluster 与 Heatmap：它们各自怎么骗人（1 h，本周重点）

> **学完你能做什么**：在控制台把 `distance`/`blur`/`radius` 一档一档调出肉眼可见的变化，说出每个参数"调大调小分别骗在哪"，并解释为什么簇上的数字和热力图的颜色都不能直接当统计口径。

**Cluster（`ol/source/Cluster.js`）—— 它包在 VectorSource 外面，把邻近要素收成一个"代表点"。类比**：把散落的橘子装进筐，筐大小（distance）你定——筐越大、筐数越少、每筐写的数字越大，"橘子总数"没变，但"地图上看见几个筐"完全取决于你买多大的筐。**Heatmap（`ol/layer/Heatmap.js`）—— 它把每个点画成一个高斯模糊的圆，再按颜色查找表（gradient）上色。类比**：把每滴墨吹开成一片晕，晕圈半径决定"看起来湿了多少"，但深浅是相对这锅水说的。

| 参数 | 作用 | 骗人的表现 |
| --- | --- | --- |
| `distance`（像素） | **聚合半径**：屏幕上相距小于这个像素数的点算一堆 | 同一份数据，`distance: 40` 显示 120 个簇、`distance: 120` 显示 9 个簇。截图对比一眼可见。屏幕像素 ≠ 地面距离，所以"密集程度"这个数字随缩放级别含义漂移 |
| `minDistance` | 簇之间最小间距，防止小簇被完全遮住 | 调大 → 视觉上"点变均匀"，但**密集区的真实集中度被抹平** |
| `threshold` | 一个像素内要素数超过它就强制合并 | 极大点数时救性能，代价是数字不可解释 |
| 缩放级别 | 视野变化会**重新聚类** | 低级别看到的"热点"，可能是十几个县共享一个点造成的假热点 |
**Heatmap 的参数（读法同上表）**：

| 参数 | 作用 | 骗人的表现 |
| --- | --- | --- |
| `blur` | 高斯模糊半径（像素） | blur 越大，两个邻近点"融成一团红"，读者以为存在一条连续的高值带 |
| `radius` | 单点影响半径（像素） | 半径放大 = 密度扩散，视觉上"热点蔓延" |
| `weight`（返回 0~1 的函数） | 每个点的权重 | **默认 1**：1 个点就可能是"最热"。有属性权重却忘了设，图会表达"数量"却读成"强度" |
| `gradient` | 颜色查找表 | **透明度衰减是默认梯度的灵魂也是陷阱**：`'rgba(0,0,255,0)' → 'blue' → 'red'`，冷色端透明度高，低密度区直接"看不见"，于是**稀疏数据看起来一片空，其实有点** |
| 归一化 | 权重按**当前要素集合的 min/max** 归一 | 最致命：**绝对值不可比**。换一份数据、加一批点，同一个位置的颜色就变了；截图 A 的"红"和截图 B 的"红"不是同一个数 |

**每个参数调大调小分别骗在哪**（E1/E2 实验前必读，脚本在练习 1）：
| 参数 | 调大 | 调小 |
| --- | --- | --- |
| Cluster `distance` | 大筐装一切：满屏只剩几个簇，读者以为"就这几个聚集点" | 几乎不聚合：簇数≈原始点数，读者以为"点很稀疏"，其实是半径小到框不住邻居 |
| Heatmap `blur` | 晕染更大：邻近热点融成一团红，"连续高值带"是脑补的 | 每点一颗孤零红丸，连续性被低估 |
| Heatmap `radius` | 热点"蔓延"，低密度区也被染色，密度感整体拔高 | 收缩成针尖大红点，读者以为"几乎没数据" |

**逐条调参实验**（在 viz-lab 页面跑；前提：`main.js` 末尾挂了 `window.viz = {map: ctx.map, layers: modes}`，写法见练习 1 第 5 步）【浏览器 DevTools→Console】：

```js
viz.layers.cluster.getSource().setDistance(30);
console.log('簇数:', viz.layers.cluster.getSource().getFeatures().length); // 预期：满屏小簇，数字多为 1~3
viz.layers.cluster.getSource().setDistance(120);
console.log('簇数:', viz.layers.cluster.getSource().getFeatures().length); // 预期：掉一个数量级，剩几个大数字簇 —— distance 是屏幕像素，这就是"骗"的开关
viz.layers.heatmap.setBlur(40);   // 预期：红团边缘化开，两个邻近热点连成一片
viz.layers.heatmap.setBlur(15);
viz.layers.heatmap.setRadius(25); // 预期：热点整体"蔓延"，橙色区扩成红色区
viz.layers.heatmap.setRadius(12); // 预期：收缩回针尖
```

失败时：数字没变 → 你操作的是内层 `vectorSource` 不是 `cluster`（坑 P5）；热力怎么调都一屏红 → `weight` 全 1 且点密（坑 P6），先 `setRadius(8)` 再看层次；整片透明 → 冷端 alpha 本来为 0（坑 P6），不是没数据。

**最阴的一点**：簇上的数字是"这一堆里有多少个原始要素"，但**原始要素可能不在视野内**（`Cluster` 默认按源内全量算）。所以"这个簇 = 8"和"屏幕上看得见 8 个点"是两件事。要展示成员，必须取 `feature.get('features')`（Cluster 把原始要素挂在成员要素的这个属性上）——练习 2 会做。

诚实做法（写进 README）：聚类的 ① 图上标"聚合半径 60px" ② 允许点开看成员 ③ 别拿簇数量做统计口径；热力图只做"找相对高低、定研究范围"的第一步，结论要回落到分级图或计数，图上必须写清 `weight` 字段与是否归一（不设 `weight` = 默认全 1，1 个点也顶格红，"数量"会被读成"强度"；整体压太低则全图落在透明冷端，"看不见"被读成"没有"）。**两者对比一句话**：聚类回答"**这里有多少个**"（离散、可数、可点验）；热力图回答"**哪里相对更密**"（连续、不可读数值、易被色带放大）。选错工具 = 把问题问错。**常见误区**：① 拿簇个数或簇数字做统计口径；② 拿两张不同数据的热力图截图比"谁更红"；③ 以为 radius 单位是米——是像素（坑 P4）。

### 1.4 矢量瓦片原理：MVT / PBF（0.6 h）

> **学完你能做什么**：用披萨类比讲清矢量瓦片的三个优势与对应代价，在浏览器 Network 面板里认出 `.pbf` 请求，并用 `queryRenderedFeatures` 证明"瓦片里带了哪些字段"。

**类比（本周最要用的一句）**：**把数据切成披萨，每块自带几何，但不带样式。**
- **切成披萨**：按 z/x/y 瓦片网格切，每块瓦片只装"落在这一块里的几何 + 顶点"，坐标是瓦片内部相对值（默认 4096×4096 的 `extent` 格网）。
- **自带几何**：所以你能在前端把它再变成点/线/面、能做命中检测、能按属性变色、能让线宽随缩放变化——**这是它相对图片瓦片的根本优势**。
- **不带样式**：切片里没有颜色、字体、图层的绘制顺序（那些写在 style 或 OL 的 `Style` 里）。所以**改配色不用重新切片**，切一万片只算一次。
- **PBF** 只是这份"披萨"的编码格式（protobuf，二进制、紧凑）；在 Network 面板里看到的就是 `.../{z}/{x}/{y}.pbf`，你在 W3 已经见过 `png` 的位置换成了 `pbf`。
**最小观察实验**【浏览器 DevTools→Network 过滤 `pbf`，在 https://demotiles.maplibre.org/index.html】：刷新页面，预期看到一列 `/tiles/{z}/{x}/{y}.pbf`（Status 200），单条只有几 KB——这就是"披萨片"。失败时：列表里只有 `png` → 你打开的是图片瓦片站点；`pbf` 超时 → 网络问题（坑 P11，启动 Steam++）。

**矢量瓦片相比图片瓦片的 3 个优势（验收项 1，可背可推）**：
1. **样式与数据分离**：前端换配色/换标注语言/加过滤不用回服务器重新渲染；一份瓦片服务多种主题（浅色、深色、夜景）。图片瓦片改一个线宽要重新切全套。
2. **无级缩放不失真 + 平滑旋转**：几何是矢量，缩放时按像素重算，不会像 png 那样出现马赛克/糊边；还能做 `pitch`/`rotation`（三维感）。
3. **可做前端交互与计算**：`queryRenderedFeatures` / OL 的 `forEachFeatureAtPixel` 能在瓦片上做点选、过滤、按属性着色，甚至简单空间判断；图片瓦片只能"看到"不能"拿到"。（附带好处：几何压缩后体积常常小于同区高清 png，一次请求可复用样式与命中。）

**代价也要说（这是与"3 优势"配对的专业素养）**：字段必须**在切片时选定**并只带进瓦片（没带的字段前端永远取不到）；瓦片边界处的要素被**切开**（label 重复、缓冲区跨块会缺）；不同层级**各自简化**（面积/长度会随 z 变化，不能拿来量算）；解析与渲染吃 CPU/GPU。

**OpenLayers 侧的接线（对照读，别急着写）**：

```js
import VectorTileLayer from 'ol/layer/VectorTile.js';
import VectorTileSource from 'ol/source/VectorTile.js';
import MVT from 'ol/format/MVT.js';

const vtLayer = new VectorTileLayer({
  source: new VectorTileSource({
    format: new MVT(),                     // 声明"pbf 里怎么还原几何"
    url: 'https://.../{z}/{x}/{y}.pbf',
  }),
  style: /* TODO: 矢量瓦片的 style 是【图层级】的，不是每要素工厂 —— 传函数时要 (feature, resolution, skill) */
});
// ⚠️ 两个专属坑：
// 1) 要素几何是"瓦片内相对坐标"，OL 已自动转换，但你手动算面积/长度会全错（不要拿它量算）
// 2) style 必须缓存在图层上（同一个 Style 对象复用），每要素 new Style 会掉帧
```

**与 MapLibre 的分工**：MapLibre 是"WebGL 矢量瓦片渲染器"，样式全部写在 `style.json`；OpenLayers 是"地图应用框架"，样式写在 JS 里。W9 的百万级数据会走 MapLibre/tileserver 这条线，本周先把 `style.json` 读懂。

**常见误区**：① "矢量瓦片带属性"≠"带全部属性"——字段切片时定死（练习 2 需求 4 亲手数）；② 拿瓦片几何量面积（坑 P7）；③ 以为换配色要重新切片（恰恰不用，这是核心卖点）。

### 1.5 MapLibre `style.json` 逐层拆解（0.8 h）

> **学完你能做什么**：拿到任何 `style.json`，用"四层心智模型"定位：数据在哪个 source、画的哪个 source-layer、叠在第几层、改 layout 还是 paint；并能在浏览器 DevTools 里一层层把 `layers` 数组翻出来看。

**类比（四层心智模型，背下来，读任何 style.json 都用它）**：① `sources` = 食材从哪个仓库取（瓦片服务/内联数据），**不知道长相**；② `source-layer` = 仓库里的哪个货架（一个 MVT 服务内可含多个图层，如 `countries` / `geolines` / `centroids`）；③ `layers[]` = 一道道菜，数组**从下往上**叠（所以 `background` 排第一，label 排最后 —— 顺序错了字就被色块埋了）；④ `layout` / `paint` = 上菜的摆盘规则（`layout` 影响几何/可见性/文字放置，会触发重排；`paint` 只是颜色线宽，改起来便宜）。

**表达式速查（练习 2 会用到）**：`["get", "字段"]`、`["==", k, v]`、`["match", ["get","x"], ["A","B"], "色1", "默认色"]`、`{ "stops": [[z, 值], …] }`（按缩放插值）、`case`（多分支条件）。看到 `[...]` 嵌套就是表达式，看到 `{...}` 带 `stops` 就是分级插值。

**常见误区**：① `source-layer` 写成 `sources` 的键名（两个东西，写错静默不显示）；② 拿改 `paint` 的心态改 `layout`（`visibility` 触发重排，大面积改会卡）；③ 以为表达式能算数——它只能读瓦片里已带的字段。

// viz-lab/src/legend-quick.js —— 复制即用，再按下面三处接线
export function createQuickLegend(containerId) {
  const box = document.getElementById(containerId);
  const fmt = (v) => (v == null ? '' : Number(v).toFixed(1));
  function render({title, method, field, unit, breaks, colors, noData, note, layer}) {
    const rows = colors.map((c, i) => {
      const lo = i === 0 ? '' : `${fmt(breaks[i - 1])} `;
      const hi = i === breaks.length - 1 ? `≤ ${fmt(breaks[i])}` : `< ${fmt(breaks[i])}`; // 与图层同一套左闭右开写法
      return `<div class="legend-row"><span class="legend-swatch" style="background:${c}"></span><span>${lo}${hi}</span></div>`;
    });
    if (noData) rows.push('<div class="legend-row"><span class="legend-swatch" style="background:#e5e7eb"></span><span>无数据</span></div>');
    box.innerHTML = `<p class="legend-title">${title}</p><p class="legend-sub">${field}（${unit}）· ${method} · ${breaks.length} 级</p>${rows.join('')}${note ? `<p class="legend-note">${note}</p>` : ''}`;
    box.dataset.owner = String(layer ? layer.get('name') : ''); // 记住自己属于哪个图层
  }
  function sync(layer) {
    if (box.dataset.owner && String(layer.get('name')) !== box.dataset.owner) return; // 只管自己那张图
    box.classList.toggle('off', !layer.getVisible());
    box.style.opacity = layer.getVisible() ? String(layer.getOpacity()) : '';          // 透明度也同步
  }
  return {render, sync};
}

## 4. 坑预告（按你的环境定制，遇到就回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | 分级边界左闭右开不统一 | 边界值要素"掉级"，图例显示 5 档但实际出现 6 种颜色（或某色从不出现） | 全项目统一 `v >= breaks[i] && v < breaks[i+1]`，最后一档用 `<=`；写一个单元测试式的 Console 验证：把 breaks 端点值造进数据里试一遍 |
| P2 | 类别字段类型不一致 | 配色全部落到 fallback 灰：`adcode` 在 GeoJSON 里是**字符串** `'440100'`，你的 map 键写的是数字 `440100` | `String(feature.get('adcode'))` 统一；或 `console.log(typeof v)` 先看类型再写映射 |
| P3 | 空值/0 被当作最低级 | 图上一片最浅色，读者以为"数据很好" | 分级前先 `filter(v => v != null)`；`0` 与 `null` 是两回事，`null` 必须走"无数据"样式 |
| P4 | 聚类数随缩放剧变，以为程序坏了 | `cluster.getSource().getFeatures().length` 数字每次拖动都在变，E1 记录不上 | 这是设计行为。固定缩放级别（如 z=10）再取数；截图前 `setZoom` 精确到整数（`constrainResolution: true` 可锁整级） |
| P5 | Cluster 里取原始要素取不到 | `feature.get('features')` 是 `undefined`，点簇没反应 | 只有**簇要素**有这个属性；`forEachFeatureAtPixel` 拿到的若不是簇，检查你的图层是否直接绑了 `vectorSource` 而不是 `cluster` |
| P6 | 热力图整片透明/整片红 | 看不到热点，或一屏全红没层次 | 冷端 `rgba(0,0,255,0)` 是**故意透明**；整片红通常是 `weight` 全为 1 且点数多 → 降 `radius`/`blur` 或给 `weight` 归一函数；记住颜色是相对值 |
| P7 | MVT 上算长度/面积 | 数值离谱，且随缩放变化 | 矢量瓦片每级各自简化、几何是瓦片内相对坐标。**不要拿它量算**，量算回到 GeoJSON + `ol/sphere`（W4 练习 4） |
| P8 | MapLibre 文字图层不显示 | symbol 图层一片空白，无报错 | `glyphs` 没配或 `text-font` 名称对不上（示例里是 `Open Sans Semibold`，必须与 glyphs URL 的 `{fontstack}` 拼得出 200） |
| P9 | `setPaintProperty` 改 match 表达式 | 传单个颜色后所有国家变成同一色 | 预期行为（paint 属性整体替换）。要么传完整 match 表达式，要么改 `fill-opacity`/加一个新图层覆盖 |
| P10 | MapLibre 与 OpenLayers 同页样式冲突 | 容器高度 0，地图只有背景色；或两个库的 CSS 打架 | 容器必须显式 `height`（`#maplibre-map{height:100%}` 加父级链）；两个库分在两个页面（`index.html` / `maplibre.html`），别混用一个容器 |
| P11 | 国外瓦片服务与示例数据时通时断 | `demotiles.maplibre.org` 或 `raw.githubusercontent.com` 超时 | W0 笔记第六节：启动 Steam++（hosts 加速）再试；练习里把成功页面的截图先存下来，别等网络恢复补 |
| P12 | Vite 多页入口没配 | 访问 `/maplibre.html` 404 | dev 下确认文件在项目根目录（与 `index.html` 同级）；build 要在 `vite.config.js` 加 `build.rollupOptions.input`（这正是 W6 的主题，提前撞一次） |
