## 1. 学（约 3 h，周一到周二）

> 本节每个小节开头都有一行「学完你能做什么」——读完一节先对照这句话自查；每个核心概念按**定义 → 类比 → 最小示例 → 常见误区**四件套讲，命令都标注了运行位置（【PowerShell】【浏览器】等）。

### 1.1 Vite 构建原理（dev vs build，45 min）

> **学完你能做什么**：能解释为什么 `npm run dev` 秒开而 `npm run build` 要等几秒；build 后白屏/环境变量失效时能说出该往 dev/build 哪一头查。

**概念四件套：dev 与 build 的区别**

- **定义**：`npm run dev` 用 esbuild 做"边请求边编译"的开发服务；`npm run build` 用 rollup 把全部代码打包成静态文件（`dist/`）。两者是两套工具，配置项不通用。
- **类比**：dev 像餐馆的**现炒**——你点一道（浏览器请求一个模块）它做一道；build 像**预制菜打包**——一次全做完装箱（dist），客人（nginx）只管加热上桌。
- **最小示例**：【PowerShell】

  ```powershell
  cd projects/webgis-starter
  npm run dev        # 预期输出：Local: http://127.0.0.1:5173/ ，秒出
  ```
  失败时：报 `Cannot find package` → 没装依赖，先 `npm install`（且别用 pnpm，W0 坑 #1）。

  ```powershell
  npm run build      # 预期输出：✓ built in Xs，生成 dist/index.html 和 dist/assets/*.js
  dir dist           # 预期输出：能看到 index.html 与 assets 目录
  ```
  失败时：`dist` 是空的 → build 报错没看全，往上翻第一条红字才是根因。

- **常见误区**：① 以为 dev 也会更新 `dist/`——不会，dist 只有 build 才写；② 改 `vite.config.js` 后以为自动生效——dev server 必须重启；③ 把 esbuild 专属选项写进 rollup 配置块，报"未知选项"。

| 阶段 | 工具 | 特点 | 典型用时（本项目） |
| --- | --- | --- | --- |
| `npm run dev` | **esbuild**（JS 解析打包极快）+ HMR（热更新） | 只做"能跑"的转换（TS → JS，模块合并），树摇/压缩/资源拷贝都不做；dev server 还会自动起 HTTP 服务 | <1 s |
| `npm run build` | **rollup**（模块化打包优化）+ terser/esbuild 压缩 + CSS 提取 | 树摇（删掉未用代码）、代码分割（chunk）、资源优化（图片/字体被复制进 public 目录）、source map | ~3~8 s（本机） |

两个关键点：

1. **dev 不需要把 dist 生成出来**，它直接从源文件编译并给页面提供 JS 模块；所以你看不到 `dist` 里的内容。`preview` 命令则是对已生成的 `dist` 提供一个静态服务容器，模拟生产环境。
2. **`.env` 变量只能被构建或运行时看到**，且 Vite 对变量有前缀限制：**以 `VITE_` 开头的才会在客户端可用**。`NODE_ENV` 等不受前缀影响，由 CLI 传入。

对照 [basemaps.js](../projects/webgis-starter/src/basemaps.js) 第 16 行的真实用法：

```js
const tiandituKey = import.meta.env.VITE_TIANDITU_KEY ?? '';
```

这条语句的含义：从**前端可以访问的环境变量**里读取密钥；没读到就空串，导致底图列表里没有天地图（见第 100 行的友好提示）。

### 1.2 环境变量与 `import.meta.env`（30 min）

> **学完你能做什么**：能把天地图 key 放进 `.env` 并在前端取到；key 没生效时按"前缀 → 重启 → 重新 build"三步自查。

**概念四件套：Vite 环境变量**

- **定义**：`.env` 是项目根目录的键值对文件，Vite 在**启动 dev server 或执行 build 那一刻**把以 `VITE_` 开头的变量注入前端代码，代码里通过 `import.meta.env.VITE_xxx` 读取。
- **类比**：`.env` 像给建筑工人（esbuild/rollup）看的**当日告示牌**——开工时抄一遍贴在墙上；开工中途改告示，工人不会回头看，必须重新开工（重启/重新 build）。
- **最小示例**：【PowerShell】

  ```powershell
  cd projects/webgis-starter
  Copy-Item .env.example .env   # 预期输出：无输出即成功
  ```
  然后用 VS Code 打开 `.env` 填入 key（【VS Code】）：

  ```bash
  VITE_TIANDITU_KEY=你的key     # 等号两边不要空格、不要引号
  ```
  预期输出：重启 `npm run dev` 后 Console **不再**出现"未配置 VITE_TIANDITU_KEY"。
  失败时：仍提示未配置 → ① 变量名少写了 `VITE_`；② 没重启 dev server；③ 文件存成了 `.env.txt`（资源管理器开了"隐藏扩展名"时高发，用 VS Code 新建文件可避免）。

- **常见误区**：① 以为改 `.env` 后页面会自动热更新——不会，环境变量注入发生在启动时；② 把 DB 密码也写进 `VITE_` 前缀变量——它会**编译进公开 JS**，谁都能看；③ 在 `.env` 值里加引号或空格，值就带着引号进了代码，key 校验失败。

细节备忘：

- **位置**：在项目根目录建 `.env`（不要公开到 Git，`.gitignore` 已包含它）。示例：

  ```bash
  # 复制到 projects/webgis-starter/.env（基于 .env.example）
  VITE_TIANDITU_KEY=你的 key（去 https://console.tianditu.gov.cn/ 申请）
  ```

- **dev 模式刷新**：改完 `.env` 后要**重启 dev server**（Ctrl+C 停止后再 `npm run dev`），否则新值仍拿不到。**build 模式**不需要重启，但需要重新 `npm run build` 才能看到变化。
- **命名规则**：前端代码里只能用 `import.meta.env.VITE_PREFIX_NAME`；其他变量（如 API 地址、DB 密码等）只能在 **Node 脚本** 里通过 `dotenv` 读，不能暴露到前端（这是安全问题，但天地图 key 属于公开 Token，可以放前端）。
- **多环境**：`VITE_APP_BASE=prod` 这样的常量，可在代码中根据条件使用，但**别搞复杂**（本教程仅用一个 `.env`）。

### 1.3 base 路径坑（30 min）

> **学完你能做什么**：能说出 `base: './'` 和 `base: '/'` 各自适用场景；部署到子路径白屏时一眼认出是 base 问题。

**概念四件套：base 路径**

- **定义**：`vite.config.js` 里的 `base` 是构建产物中所有资源 URL 的**前缀**。`base: './'` 生成相对路径 `./assets/app.js`；`base: '/'` 生成绝对路径 `/assets/app.js`。
- **类比**：base 是**信封上的地址写法**。写"本市 xx 路"（相对）在本市怎么转送都能到；写"xx 路 1 号"没写城市（绝对 `/`），出了本市（子路径）就投递失败。
- **最小示例**：【VS Code】打开 [vite.config.js](../projects/webgis-starter/vite.config.js) 第 5 行：

  ```js
  base: './',
  ```
  【PowerShell】`npm run build` 后验证：

  ```powershell
  Select-String -Path dist/index.html -Pattern 'src='
  ```
  预期输出：`src="./assets/index-xxxx.js"`（带 `./`）。
  失败时：看到 `src="/assets/..."` → base 是 `'/'`，子路径部署会 404（坑 P3/P9）。

- **常见误区**：① 以为 base 只影响 HTML——JS 里动态 import、CSS 里的 url() 都受影响；② 在 GitHub Pages 子路径用 `/` 还说"我本地没问题"——本地 dev 跑在根路径所以掩盖了。

`vite.config.js` 中的 `base` 选项决定了**构建产物相对 URL 的前缀**：

- `base: '/'`：假设网站挂在域名根路径（如 `https://example.com/app` 应写成 `https://example.com`，并且所有静态资源 URL 为 `/xxx.js`）。
- `base: './'`（当前 starter 默认）：适用于子路径或相对路径部署（如在 GitHub Pages 上部署到 `user.github.io/myproject`）。此时 HTML/JS/CSS 引用都用相对路径（`./app.js`），避免 404。

**为什么写错会白屏？** 如果 `base` 设为 `'/'`，但你在子路径下访问，例如 `localhost:8080/gis`，而 HTML 里引用了 `/app.js`，服务器找不到这个文件就会 404，控制台报错，页面白屏。反之，若你设在根路径却用了 `./` 前缀，则在某些场景下也会出错。

### 1.4 Nginx 反向代理原理（45 min）

> **学完你能做什么**：能逐行讲出下面这份 `nginx.conf` 每行干什么、删了会怎样；能解释为什么浏览器不再报 CORS。

**概念四件套：反向代理**

- **定义**：反向代理是站在服务器侧的"中转人"：浏览器只访问 nginx（`http://localhost:8080`），nginx 按规则把 `/geoserver/...` 转发给真正的 GeoServer，再把响应递回浏览器。
- **类比**：公司**前台**。客户（浏览器）只跟前台打交道，不知道也不直接进研发部（GeoServer 的 8080 内网端口）；客户和前台说同一种话（同源），自然没有"跨公司拜访"（跨域）的安检。
- **最小示例**：下面 `location /geoserver/` 那 8 行就是最小可用单元。
- **常见误区**：① 以为 CORS 是前端的问题——决定权在**响应头**，前端改不了；② 在浏览器里加插件绕 CORS 然后部署上线又翻车——插件只救你自己那台机器；③ 以为 nginx 改了配置自动生效——必须 `docker exec webgis nginx -s reload` 或重启容器。

**反向代理是什么**？用户访问的是 `http://your-domain/api/geoserver`，你的服务器上运行了一个 Nginx，它会代表你调用真正的 GeoServer（或其他服务），再返回结果给用户。这样做的好处有两点：

1. **隐藏后端服务地址和端口**；
2. **解决跨域问题（CORS）**：因为请求看起来是同源的，浏览器就不再拦截。

**nginx.conf 逐行注释版**（每行干什么、错了会怎样）：

```nginx
server {
    listen       80;                       # 容器内监听 80 端口。写错成 8080 → docker -p 8080:80 映射落空，浏览器超时
    server_name  localhost;                # 匹配的域名/IP。学习期用 localhost；上线写域名，写错→请求落到别的 server 块

    root         /usr/share/nginx/html;    # 静态文件根目录 = 你的 dist 挂载点。目录挂错 → 403/404（坑 P2）
    index        index.html;               # 访问 / 时默认给的文件。dist 里没有 index.html → 403 Forbidden

    location / {
        try_files $uri $uri/ /index.html;  # SPA 兜底：先找真实文件→再找目录→最后回 index.html。
                                           # 删掉它 → 前端路由页面刷新时报 404（vue-router/react-router 用户必踩）
    }

    # 反向代理 GeoServer（解决 CORS）
    location /geoserver/ {                 # 匹配以 /geoserver/ 开头的请求。少了末尾 / 会连 /geoserverXXX 也匹配
        # 注意：去掉前缀 /geoserver/ 后的部分
        rewrite ^/geoserver/(.*)$ /$1 break;   # 把 /geoserver/wms 改写成 /wms 再转发。删掉 → GeoServer 收到
                                               # /geoserver/wms，路径错位 404（坑 P7）
        proxy_pass http://geo-container:8080;  # 真正的后端地址（docker-compose 服务名）。IP 写错 → 502 Bad Gateway
        proxy_set_header Host $host;           # 把原始 Host 头带给后端。删掉 → GeoServer 生成的 URL 里主机名错乱
        proxy_set_header X-Real-IP $remote_addr; # 让后端日志看到真实访客 IP，而非 nginx 的 IP
        add_header Access-Control-Allow-Origin *;              # CORS 头①：允许任何来源。学习期用 *，生产收窄成域名
        add_header Access-Control-Allow-Methods 'GET, POST, OPTIONS'; # CORS 头②：允许的方法
        add_header Access-Control-Allow-Headers 'DNT,X-CustomHeader,Keep-Alive,User-Agent,X-Requested-With,If-Modified-Since,Cache-Control,Content-Type';
        # ↑ CORS 头③：允许的请求头。Content-Type 漏了 → WFS 的 POST XML 请求被拦（坑 P6）
    }

    # 可选：静态资源缓存
    location ~* \.(png|jpg|jpeg|gif|webp|svg|ico|css|js|json)$ {  # 正则匹配静态资源扩展名
        expires 7d;                      # 浏览器缓存 7 天。改版后用户看到旧页面 → 改文件名（vite 自带 hash）或调短
        access_log off;                  # 瓦片/图片不写访问日志，日志体积小一个量级
    }
}
```

改完配置后的验证动作（【PowerShell】）：

```powershell
docker exec webgis nginx -t     # 预期输出：syntax is ok / test is successful；失败时按行号回去查分号、花括号
docker exec webgis nginx -s reload   # 不重启容器热加载；没做这步 → 新配置不生效
```

要点说明：

- `rewrite ^/geoserver/(.*)$ /$1 break;`：去掉 `/geoserver` 前缀再转发到 GeoServer；
- `add_header ...` 增加 CORS 头：让前端请求不被浏览器拦截；
- `try_files`：单页应用（SPA）的路由兜底，避免刷新时报 404。

### 1.5 Docker 挂载 dist（30 min）

> **学完你能做什么**：能在 Windows Docker Desktop 下用三种写法挂载 dist；看到 `invalid mount config` 能立刻说出是路径格式问题。

**概念四件套：卷挂载（volume/bind mount）**

- **定义**：挂载 = 把容器里的某个目录"指向"容器外的一块存储。容器删了，外面的数据还在。
- **类比**：**U 盘插槽**。容器是租来的游戏机，存档在 U 盘（卷）里；机器退了，存档不丢。
- **最小示例**：下面两种命令任选其一跑通即可。
- **常见误区**：① 在 PowerShell 里写 `D:\xx\dist`（反斜杠）——Docker 报 `invalid mount config`（坑 P1）；② 挂载后发现目录是空的——Windows 源路径不存在时 Docker **静默创建空目录**挂进去，不报错（坑 P2）；③ 在 Git Bash 里写 `D:/xx/...` 不加斜杠前缀——Git Bash 会做路径转换把 `:` 吃掉，前面加 `//` 或用 `MSYS_NO_PATHCONV=1`。

**Windows Docker Desktop 路径写法对照表**（同一个 dist，三种合法写法）：

| 写法 | 完整命令片段 | 适用终端 | 注意 |
| --- | --- | --- | --- |
| ① 正斜杠 Windows 路径 | `-v D:/xx/deepseek/default-workspace/projects/viz-lab/dist:/usr/share/nginx/html` | PowerShell / CMD | **推荐**：最直观；路径含空格时整段加双引号 `"-v D:/my dir/dist:/usr/..."` |
| ② Git Bash 风格 `/d/...` | `-v /d/xx/deepseek/default-workspace/projects/viz-lab/dist:/usr/share/nginx/html` | Git Bash | Docker Desktop 也认识；在 PowerShell 里这样写会失败；Git Bash 里若被路径转换坑，命令前加 `MSYS_NO_PATHCONV=1` |
| ③ 命名卷 | `docker volume create webgis-dist` 然后 `-v webgis-dist:/usr/share/nginx/html` | 任意 | 不涉及宿主机路径，最省心；但**文件要先进卷**（见下方"怎么把 dist 灌进命名卷"） |

怎么把 dist 灌进命名卷（【PowerShell】，用一次性 alpine 容器当搬运工）：

```powershell
docker run --rm -v webgis-dist:/to `
  -v D:/xx/deepseek/default-workspace/projects/viz-lab/dist:/from `
  alpine sh -c "cp -r /from/* /to/"
# 预期输出：无输出即成功
# 失败时：报 No such file → 检查 /from 路径； permission denied → 目标卷被占用容器锁住
```

两种方案都要会用：

**1）命名卷（推荐）**：

```powershell
docker volume create webgis-dist
docker run -d -p 8080:80 --name webgis \
  --mount source=webgis-dist,target=/usr/share/nginx/html \
  nginx:alpine
```

优点：路径在 Linux 容器内统一（`/usr/share/nginx/html`），不涉及 Windows 路径转义；命名卷在 `docker compose up -d` 时也能一致工作。

**2）bind mount（Windows Docker Desktop）**：

```powershell
docker run -d -p 8080:80 --name webgis \
  --mount type=bind,source="D:/xx/deepseek/default-workspace/projects/viz-lab/dist",target=/usr/share/nginx/html \
  nginx:alpine
```

注意两点：

- 使用 **正斜杠 `/`** 而非反斜杠 `\`；
- 如果是带空格的路径，建议加引号并用正斜杠；或者使用短路径格式（如 `D:/gis/viz-lab/dist`）。

### 1.6 `.env` 注入天地图 key（20 min）

> **学完你能做什么**：能复述 key 从 `.env` → JS bundle → 瓦片请求的完整链路；瓦片 403 时知道去天地图控制台查 referer 白名单。

按照 [basemaps.js](../projects/webgis-starter/src/basemaps.js) 的写法，步骤是：

1. 创建 `.env`（不提交进 Git），写入 `VITE_TIANDITU_KEY=你的 key`；
2. 确保 `.env` 不在 `.gitignore` 之外（starter 的 `.gitignore` 已排除 `.env`，保证安全）；
3. dev 模式下修改 `.env` 后重启 server，build 后重新 `npm run build`；
4. 生产镜像中，Nginx 只是发静态资源，key 已经编译进 JS bundle，不再需要额外配置。

## 4. 坑预告（按你的环境定制，遇到就回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | **Windows Docker Desktop 挂载路径风格不对**（`C:\Users\...` 带反斜杠） | `docker run` 失败：`invalid mount config for type bind` 或路径不存在 | 使用正斜杠 `/d/xx/...`，或用命名卷替代；避免反斜杠；Windows 下路径最好不带空格，否则加双引号 |
| P2 | **Docker 容器内路径与 Windows 路径混淆** | 映射目录为空，`docker exec -it webgis ls -la /usr/share/nginx/html` 看不到文件 | 确认 bind mount 源路径是绝对路径且已存在；容器内目标路径固定为 `/usr/share/nginx/html`；用 `docker logs` 看 Nginx 访问日志确认访问路径是否正确 |
| P3 | **`base` 路径设成 `/` 但部署在子路径** | 访问子路径时 `index.html` 正常，但所有 JS/CSS 报 404 | `vite.config.js` 中用 `base: './'`；或在真正根路径部署时用 `/`；测试时用 `npx serve` 模拟子路径 |
| P4 | **改完 `.env` 不重启 dev server** | 开发期新 key 无效，Console 提示"未配置" | Vite 仅在启动时注入环境变量；改 `.env` 后务必 `npm run dev` 重启（kill 旧进程再 start） |
| P5 | **build 后不重新 build** | 刚改完 `.env` 就跑 `docker run`，key 仍为空 | build 时才把环境变量编译进 JS 包；改 `.env` → `npm run build` → `docker restart webgis` |
| P6 | **nginx 的 CORS 头加错位置** | `access-control-allow-origin` 在 Nginx 配置里没有生效，请求仍报错 CORS | 在 `location /geoserver/` 块里加 `add_header Access-Control-Allow-Origin *;`；并确保 `if` 块没有覆盖这些 header |
| P7 | **Nginx 配置中 `proxy_pass` 缺少末尾斜杠** | `/geoserver/wms?REQUEST=GetMap` 请求变成 `/geoserver/geoserver/wms` | `proxy_pass http://geo:8080` vs `http://geo:8080/` 的区别会影响前缀拼接；rewrite + break 配合使用 |
| P8 | **Docker 容器端口被占用** | `docker run -p 8080:80` 报错 `Address already in use` | `netstat -ano | findstr :8080` 查看哪个进程占用；改为 `-p 8081:80` 或杀掉占用进程 |
| P9 | **`dist/index.html` 中 script 标签是 `src="/assets/xxx.js"` 而非 `./`** | 访问 `http://localhost:8080/gis` 子路径时报 404 | `vite.config.js` 中 `base: './'` 是关键；重新 `npm run build` 验证输出路径 |
| P10 | **天地图 key 失效或被误绑 referer** | Tiled 图层返回 403，Network 面板看到 403 状态码 | 在天地图控制台中确保 referer 白名单包含 `127.0.0.1` 或 `localhost`；检查 key 是否过期或已被禁用 |
| P11 | **Vite 插件配置冲突** | 多页入口配置后，`npm run dev` 报错 `Input file is missing` | 确保 `vite.config.js` 的 `build.rollupOptions.input` 指向正确的 `.html` 文件；开发模式下通常不需要多页配置 |
| P12 | **国外瓦片服务与示例数据时通时断** | `raw.githubusercontent.com` 或 `demotiles.maplibre.org` 超时 | W0 笔记第六节：启动 Steam++（hosts 加速）再试；将成功截图先保存，避免依赖实时网络 |
