## 1. 学（约 5 小时，周一到周三）

### 1.1 从 docker run 到 docker compose（0.5 h）

**学完你能做什么**：能把一串手敲的 `docker run` 命令翻译成一个 `docker-compose.yml` 文件，并用 `docker compose up -d` 一键起全套。

Compose 概念四件套：
- **定义**：Compose 是 Docker 官方的"多容器编排"工具——把多个容器的镜像、端口、卷、环境变量、启动顺序写进一个 YAML 文件，一条命令统一拉起。
- **类比**：`docker run` 是手动挡逐个挂挡，compose 是自动挡踩油门；`docker-compose.yml` = 项目拓扑的"施工图纸"，`docker compose up -d` = 照图施工。
- **最小示例**：

```yaml
# 最小可跑 compose：只有一个服务。运行位置：PowerShell，cd 到含本文件的目录
services:
  db:
    image: postgis/postgis:16-3.4
    environment:
      POSTGRES_PASSWORD: postgres
    ports:
      - "5432:5432"
```

配套命令三连（运行位置：PowerShell，与该 yml 同目录）：

```powershell
docker compose up -d        # 后台启动
```

> **预期输出**：`[+] Running 2/2 ✔ Network ... ✔ Container xxx-db-1 Started`
> **失败时**：报 `port is already allocated` → 你的旧 `pgis` 容器占着 5432 → `docker stop pgis` 再试（同款 P1 坑）。

```powershell
docker compose ps           # 看状态
```

> **预期输出**：一行 `STATUS` 为 `Up x seconds (healthy/unhealthy 或空白)`
> **失败时**：列表为空 → 你没在 yml 所在目录执行（compose 按目录找文件），`cd` 回去。

```powershell
docker compose down         # 停止并删容器（不删卷）
```

- **常见误区**：① 以为 compose 是另一个 Docker——它就是 `docker` 命令的子命令（旧版才要单独装 `docker-compose`，注意中间有没有横杠）；② 以为 `down` 会删数据——不加 `-v` 不删卷，加了才删（P6）；③ 以为端口映射左右可以互换——永远是 `宿主机:容器`。

### 1.2 compose 文件五大块逐段精讲（1.5 h）

**学完你能做什么**：看懂下面这份全注释 compose 的每一行；能回答"删掉这一段会怎样"；能独立写出 db+geoserver+web 三服务版本。

完整示例（放进 `deliver/`，注释即课文——先读注释，练习 1 再改造成你自己的）。**每段末尾的 ☠️ 注释回答"如果删掉这段会怎样"**：

```yaml
# docker-compose.yml —— db + geoserver + web 三服务
# 启动：docker compose up -d   停止：docker compose down（加 -v 会删数据卷，慎用！）
# 看状态：docker compose ps    看某服务日志：docker compose logs -f geoserver

services:                    # ── 服务清单：每个 key 是一个容器，key 名就是内部主机名
  db:                        # 服务名"db"：其他服务里写 db 就能连到它（不是 localhost！）
    image: postgis/postgis:16-3.4     # 和你 W0 手动 run 用的同一镜像
    environment:             # 容器内环境变量：官方镜像靠它初始化管理员密码与库名
      POSTGRES_PASSWORD: ${DB_PASSWORD}   # 从同目录 .env 读，不把密码写死进文件（进 Git 的是 .env.example）
      POSTGRES_DB: gisdb
      # ☠️ 删掉 POSTGRES_PASSWORD：官方镜像首次启动直接拒绝，日志报 "no password supplied"
      # ☠️ 删掉 POSTGRES_DB：只会建默认库 postgres，你的 gisdb 不存在，后面连接全报 database "gisdb" does not exist
    volumes:                 # ── 数据持久化：命名卷 pgdata 挂到镜像内数据目录
      - pgdata:/var/lib/postgresql/data   # 左"命名卷:容器内路径"。down 不清 -v 数据就在；删卷=库没了
      # ☠️ 删掉这段：数据写进容器可写层，docker compose down 后数据随容器一起消失——换台电脑更是从零开始
    healthcheck:             # 探活：容器"起了"≠数据库"能接连接"
      test: ["CMD-SHELL", "pg_isready -U postgres -d gisdb"]  # 这条命令 0=健康
      interval: 10s          # 每 10 秒问一次
      timeout: 5s            # 单次超 5 秒算失败
      retries: 5             # 连败 5 次才判 unhealthy
      start_period: 30s      # 头 30 秒失败不计数（数据库初始化需要时间）
      # ☠️ 删掉整个 healthcheck：下方 geoserver 的 condition: service_healthy 直接失效（compose 报
      #    dependency failed / 或永不放行）；退回"只等进程起来"模式，P3 的连空库重启循环回归

  geoserver:
    image: docker.osgeo.org/geoserver:2.25.2
    depends_on:              # 声明启动顺序；加 condition 才等"健康"而非只等"起进程"
      db:
        condition: service_healthy    # 靠上面 healthcheck 的结果放行，防 GeoServer 连空库反复崩
      # ☠️ 删掉 depends_on：compose 并行起两个容器，GeoServer 抢先在 db 就绪前连库 → 启动失败反复重启（P3）
    environment:             # GeoServer 官方镜像的扩展环境变量：启动即自动接 PostGIS datastore
      GEOSERVER_ADMIN_USER: admin
      GEOSERVER_ADMIN_PASSWORD: ${GS_ADMIN_PASSWORD}
      SYSDPROPS_BACKEND_TYPE: postgis
      SYSDPROPS_DB_BACKEND_HOST: db          # ★ 服务名，不是 localhost
      SYSDPROPS_DB_BACKEND_PORT: "5432"      # ★ 端口是 db 容器内端口，不是宿主机映射端口
      SYSDPROPS_DB_NAME: gisdb
      SYSDPROPS_DB_USER: postgres
      SYSDPROPS_DB_PASSWD: ${DB_PASSWORD}
      # ☠️ 把 HOST 改成 localhost：容器内 localhost=geoserver 自己，连接被拒，日志循环 Connection refused（P2）
    ports:                   # 宿主机端口:容器端口。8080 已被你 W8 手动起的旧容器占了——先 docker rm（坑 P1）
      - "8081:8080"          # 学习期避让：宿主机用 8081 进，容器内仍是 8080
      # ☠️ 删掉 ports：服务照常跑、服务间互访正常，但宿主机浏览器永远打不开它——ports 只服务"外面的人"
    volumes:
      - gs_data:/opt/geoserver_data_dir     # 命名卷存 GeoServer 配置，重建容器不丢图层
      # ☠️ 删掉这段：重建容器后你发布的所有图层/样式全没，等于每次交付都要手工重配一遍 GeoServer
    healthcheck:
      test: ["CMD-SHELL", "curl -sf http://localhost:8080/geoserver/web/ || exit 1"]  # 容器内自检，这里的 localhost 指自己，合法
      interval: 15s
      timeout: 10s
      retries: 5
      start_period: 90s      # GeoServer 启动是真的慢（JVM），耐心值给足
      # ☠️ start_period 删掉：JVM 还没热身就连败 5 次被判 unhealthy，web 永不放行，compose ps 卡 unhealthy

  web:                       # 前端：W6 学过的 nginx 托管，本周用多阶段镜像（1.3）
    build: ./web             # 用 ./web/Dockerfile 现场构建镜像（image+build 同时写则 build 产 image）
      # ☠️ build 路径写错或 Dockerfile 缺失：compose build 报 "Cannot locate specified Dockerfile"
    depends_on:
      - geoserver
    ports:
      - "80:80"
      # ☠️ 删掉：页面打不开，但其实其他两服务都在跑——排查时先 compose ps，别急着怀疑代码
    environment:
      API_KEY: ${API_KEY}    # W11 的 /ask 后端所需；生产静态站其实不该发 key，见已知问题模板

volumes:                     # ── 命名卷声明：不写则 compose 报警；数据与容器生命周期解耦
  pgdata:
  gs_data:
  # ☠️ 删掉整段但上面还在引用 pgdata/gs_data：compose 警告并自动隐式创建匿名卷，能用但卷名失控，
  #    docker volume ls 一堆乱码卷，运维时找不到数据在哪

networks:                    # ── 网络声明：不写也有默认网络，显式写清是规范做法
  default:                   # 本项目所有服务自动进同一张隔离网络，服务名 DNS 就在它上面
    name: gis-deliver-net
  # ☠️ 删掉整段：compose 自动建一个 <目录名>_default 网络，功能等价，只是名字不可控；
  #    真正会出事的是你以为"不在同一网络也能用服务名互访"——跨项目容器默认网络不通
```

自查命令（运行位置：PowerShell，`deliver/` 目录）：

```powershell
docker compose config
```

> **预期输出**：渲染出完整 YAML，所有 `${...}` 已替换为 .env 里的真实值，无 warning。
> **失败时**：`Warning: DB_PASSWORD is not set` → 坑 P5（.env 不在同目录/没写/有 BOM）。

必背三条（都来自上图，理解到能默写）：
- **ports 是给"宿主机外面的人"用的**（浏览器访问 GeoServer 用 `localhost:8081`）；**服务互连用服务名+容器端口**（web 调 geoserver 写 `http://geoserver:8080`）。两条路径别混。
- **depends_on 默认只管启动顺序不管就绪**；配 `condition: service_healthy` + healthcheck 才是"等真能用"。
- **`${VAR}` 插值来自 `.env`**（与 compose 同目录）；`docker compose config` 可渲染最终效果自查，变量没定义会警告。

### 1.3 前端多阶段 Dockerfile（1 h）

**学完你能做什么**：看懂多阶段 Dockerfile 里每个阶段的**产物是什么、最终镜像里没有什么**；能解释为什么最终镜像只有几十 MB 而构建过程用了几百 MB。

"多阶段"概念四件套：
- **定义**：一个 Dockerfile 里写多个 `FROM`，每个 `FROM` 开启一个独立阶段；后阶段可以用 `COPY --from=前阶段` 只拿走产物，前阶段的整个环境不进最终镜像。
- **类比**：工厂车间和门店——货出厂了，车间不搬进店里。打包 JS 要 Node（几百 MB + 全套 dev 依赖），**跑静态文件只要 nginx（几十 MB）**。
- **最小示例**（`web/Dockerfile`，逐行注释版）：

```dockerfile
# ── 阶段 1：builder，用 Node 24 把 Vite 项目编译成 dist 静态文件 ──
FROM node:24-alpine AS builder          # 阶段命名 builder，供下面 --from 引用
WORKDIR /app
COPY package.json package-lock.json ./  # 先只拷依赖清单：源码变动时这一层缓存不失效，重建飞快
RUN npm ci                              # CI 级安装，锁定 lockfile（npm 不是 pnpm——W0 坑 #1）
COPY . ./                               # 再拷源码（顺序反了缓存就白做）
RUN npm run build                       # 产出 /app/dist。天地图 key 若走 VITE_ 注入，
                                        # 构建参数传：RUN npm run build --build-arg 详见练习 3

# ── 阶段 2：runtime，纯净 nginx 只要产物 ──
FROM nginx:alpine
COPY --from=builder /app/dist /usr/share/nginx/html   # 跨阶段拷产物，Node 层不进最终镜像
COPY nginx.conf /etc/nginx/conf.d/default.conf        # 反代规则见下
EXPOSE 80
```

- **每阶段的产物**：
  - 阶段 1（builder）产物 = `/app/dist/` 一摞静态 html/js/css，外加一个"用完即弃"的 Node 构建环境；
  - 阶段 2（runtime）产物 = 最终镜像，内容 = nginx + 你的 dist + 反代配置，仅此而已。
- **最终镜像里没有什么**：没有 node、没有 npm、没有 node_modules、没有你的源码（src/、.env、.git 都不在）。这既是体积优势（约 40 MB vs 几百 MB），也是**安全优势**——源码和构建期密钥不进交付物。
- **常见误区**：① 以为写两个 FROM 会产两个镜像——只有最后一个阶段的产物是镜像，前面的被丢弃（可用 `docker build --target builder` 单独构建中间阶段调试用）；② 在阶段 2 还想 `npm run`——最终镜像里没有 node，命令不存在；③ 用 `COPY . .` 时忘了 `.dockerignore`，把 `node_modules/`、`.env` 拷进构建上下文——慢且泄密（`.dockerignore` 语法与 `.gitignore` 相同，至少写 `node_modules`、`dist`、`.env`）。

配套 `web/nginx.conf`（把 W3 学的"同源代理"落地成生产形态——前端 `/geoserver`、`/ask` 全走同源，浏览器零 CORS 问题）：

```nginx
server {
  listen 80;
  root /usr/share/nginx/html;
  location / { try_files $uri $uri/ /index.html; }   # SPA 刷新不 404（删掉：刷新 /about 之类路由 404，坑 P7）
  location /geoserver/ { proxy_pass http://geoserver:8080/geoserver/; }  # ★ 服务名
  location /ask        { proxy_pass http://ai-backend:3000/ask; }        # W11 原型容器化后接这里
}
```

构建验证命令（运行位置：PowerShell，`deliver/` 目录）：

```powershell
docker compose build web
```

> **预期输出**：`[+] Building ... FINISHED`，末尾 `=> => naming to docker.io/library/deliver-web`。
> **失败时**：卡在 `npm ci` 超时 → 坑 P9（换 npmmirror 源）；报 `package-lock.json not found` → 你的 web/ 里没有 lockfile，先在本地 `npm install` 生成一份（lockfile 是 `npm ci` 的前提）。

### 1.5 演示视频脚本结构（0.5 h）

分镜表（练习 3 的提纲就按此写；每格里的口播要点是"关键词"，不是逐字稿——写逐字稿必然念稿）：


5. 起 web（先跑 1.3 的 Dockerfile：`docker compose build web`，再 `up -d`），浏览器 `http://localhost` 看地图，底图叠加 GeoServer 图层（走 nginx `/geoserver` 代理，Network 面板确认请求同源——W3 知识回收）。

6. **验收动作**：`docker compose down -v`（删净卷）→ 重新 `up -d` + 重导数据 → 全链路再通一遍。跑不通说明有步骤依赖了你机器上的"记忆"，补进 README。

## 4. 坑预告（按你的环境定制，遇到就回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | W8 手动 `docker run` 的 GeoServer 容器还占着 8080 | compose 起 geoserver 报 `Bind for 0.0.0.0:8080 failed: port is already allocated` | `docker ps -a` 找到旧容器名 → `docker stop 旧名 && docker rm 旧名`（数据若要留：先 `docker cp` 出图层配置）；或新服务映射改 `8081:8080` |
| P2 | compose 里给 GeoServer 配库主机写 `localhost` | GeoServer 日志循环 `Connection refused`，datastore 连不上 | 容器内 localhost=自己。**写服务名 `db` + 容器端口 5432**；web/ai-backend 互连同规则（认知 1） |
| P3 | 只写 `depends_on: db` 没配 healthcheck | db"起来了"但还没就绪，GeoServer 首连失败反复重启 | `condition: service_healthy` + db 的 `pg_isready` 探活（1.2 示例已给）；start_period 给足初始化时间 |
| P4 | 宿主机目录挂载（bind mount）在 Windows 下权限/性能异常 | 挂载的 SQL 脚本容器读不到（`Permission denied`）或 IO 极慢 | 优先**命名卷**；确需挂文件时路径纯英文（W2 坑 P1 同款）、Docker Desktop 设置里确认该盘已 File sharing 启用；`docker compose exec` 进容器 `ls` 验证真挂上了 |
| P5 | `.env` 变量没生效/没定义 | compose 警告 `Warning: DB_PASSWORD is not set`，容器里密码成了空串 | `.env` 必须与 yml 同目录、无 BOM 无引号内空格；`docker compose config` 渲染最终配置自查；改完 `.env` 要 `up -d --force-recreate` |
| P6 | `docker compose down -v` 手滑 | 库和数据卷一夜蒸发 | `-v` 删**命名卷**（数据所在）；日常只用 `down`。测试数据也先 `pg_dump` 出仓库 `deliver/sql/seed.sql` 再折腾——这本身就是交付物该带的 |
| P7 | 前端镜像构建成功但页面白屏/404 | nginx 找不到 SPA 路由，或 build 阶段 VITE_ 变量没注入 | `nginx.conf` 加 `try_files ... /index.html`；Vite 生产 `base` 配 `/`（W6 学过）；浏览器 Console 看静态资源请求路径；`docker compose logs web` 配合 |
| P8 | WSL2/Docker Desktop 内存吃紧，三容器同起卡死 | GeoServer JVM 启动奇慢、healthcheck 总超时 | Docker Desktop → Resources 调高内存（≥8GB 富余）；`start_period` 加到 120s；还不行先只起 db+web 两服务验证链路分段 |
| P9 | `npm ci` 在容器里极慢/超时 | build 卡在依赖安装层 | Dockerfile 里 `npm config set registry https://registry.npmmirror.com`（W0 已配镜像源经验复用），再 `RUN npm ci` |
