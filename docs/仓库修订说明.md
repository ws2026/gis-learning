## 二、逐项修改明细（问题 → 理由 → 改法）

### 1. notes/week02.md：合并重复坑表

- **问题**：第二节"踩过的坑"列了 N12~N16 共 5 条；第六节"踩坑补充"又把 N12~N16 原样重写一遍、追加 N17~N19。同一编号出现两次，根因/解法措辞还略有不同（如 N15 一处写"取消勾选 parent 字段"，另一处多给了 `ogr2ogr -select` 方案）。
- **为什么要改**：坑表的价值在于"编号唯一、一条一个坑、以后能引用"（W3 手册的坑预告就靠"见 week02 N15"这类引用定位）。编号冲突会让未来的自己不知道哪条是真的。
- **怎么改的**：以**信息更全的第六节版本**为基准合并进第二节，保留 N12~N19 全部 8 条、一条不丢；删除第六节整节；原第七节"验收自检"顺位改为第六节。合并后全文只有一张坑表。

### 2. README.md：删除随手笔记行

- **问题**：标题下第二行是"今天学习下载git和配置GitHub"——这是仓库第一天的状态记录，不是项目介绍。
- **为什么要改**：README 是作品集的门面（主计划"求职衔接"一节明确说招聘的人会看仓库）。第一行就出现日记式残句，会削弱"完整交付"的印象。
- **怎么改的**：删除该行，标题下直接进入"学习计划"目录。

### 3. README.md：新增"仓库结构"与数据双份约定

- **问题**：审查时用哈希对比发现 `data/clean/gx_fixed.geojson` 与 `projects/webgis-starter/public/data/gx_fixed.geojson` **字节完全相同**（各 48.7 KB），仓库里没有任何文字解释为什么同一份数据存两处、改哪一份生效。
- **为什么要改**：这是数据管线的经典分叉点——一周后你大概率会只改其中一份，然后陷入"我明明改了数据页面怎么没变"的玄学排查（这正是主计划学习规则第 4 条说的"数据或缓存三选一"）。
- **怎么改的**：README"学习计划"与"进度"之间插入一节：目录树四行（docs / notes / data / projects 各干什么）+ 引用块写清约定：**`data/clean/` 是母本，前端用的那份是复制品；改了母本必须重新复制，否则前端还是旧数据**。

### 4. .gitignore：补 `__pycache__/`

- **问题**：现有规则忽略了 node 侧产物（node_modules、dist、.pnpm-store），但没有 Python 侧的。
- **为什么要改**：W11 的 AI 原型、W13+ 轨道 C 都会写 Python，解释器运行时会生成 `__pycache__/` 目录；不忽略的话 `git add .` 会把编译缓存一起提交进去。
- **怎么改的**：在 `.pnpm-store/` 后加一行 `__pycache__/`。
