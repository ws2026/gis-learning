> 对应《WebGIS 12 周学习计划》W2。建议时间：2026-10-13 ~ 2026-10-19（每天 1.5~2 h）。
> 环境前提：QGIS LTR 3.44.15（含 OSGeo4W Shell 的 ogr2ogr）、`webgis` conda 环境（geopandas 1.2.0）、`webgis-starter` 可跑。
> 承接 W1：本周你要把"坐标系认知"用在一份**真实下载的数据**上——它会故意让你踩一次 W1 埋好的坑。
> 本周主线一句话：**从网站下载一份真实边界数据 → 体检 → 瘦身到 100 KB 以内 → 查几何有没有毛病 → 加字段配色 → 拖进自己的网页里显示出来。** 走通这条线，以后任何"给我一份数据让我看看"的需求你都有套路。

## 0. 本周要建立的三个认知

| # | 认知 | 为什么重要 |
| --- | --- | --- |
| 1 | **格式只是容器，几何 + 属性 + CRS 才是数据本身** | 选错容器只是难用，丢 CRS 是灾难（.prj 丢失） |
| 2 | **简化（simplify）是"精度换体积"的商业决策**，容差单位是坐标系单位 | 4326 下 0.001 = 约 111 米；3857 下 0.001 = 1 毫米，同样的数字天差地别 |
| 3 | **无效几何是上线前的必查项**，自相交的面在缓冲区/相交分析时静默出错 | 不报错、结果错，是最阴险的 bug 类型 |

## 1. 学（约 3~4 小时，分散在周一周二）

### 1.1 格式对照表（自己抄一遍进笔记，抄的过程就是记）

> **学完你能做什么**：给你任何一个空间数据文件，你能一眼说出它是什么格式、坐标系存在哪、适合不适合拿来干手头的活。

先给"格式"这个概念四件套：

- **定义（一句话）**：空间数据格式 = 把"几何形状 + 属性表 + 坐标系声明"这三样东西打包存盘的约定，就像快递的包装规格。
- **类比**：同一箱苹果（数据本身），可以装纸盒（GeoJSON）、木箱（Shapefile）、保温箱（GPKG）。换箱子苹果不变，但有的箱子会把清单（.prj）贴在外面，一撕就丢。
- **最小示例**：【PowerShell】看一个文件多大、什么格式，直接 `Get-Item 440100_full.json | Select-Object Length`，再【OSGeo4W Shell】`ogrinfo -so 440100_full.json` 看里面装了什么。
- **常见误区**：① 以为"转成 GeoJSON 就万事大吉"——转格式不改数据内容，垃圾进垃圾出；② 以为 `.shp` 一个文件就是全部——它是个"文件团伙"，少一个就残废；③ 以为 GeoJSON 一定带坐标系声明——RFC 7946 之后默认 4326，**很多工具干脆不写**，你得自己知道。

| 格式 | 容器 | CRS 存哪 | 适合场景 | 坑 |
| --- | --- | --- | --- | --- |
| Shapefile | 至少 4 个文件（.shp/.shx/.dbf/.prj） | .prj（**可丢失**） | 国内交付标配 | 字段名 ≤10 字符、编码易乱码（GBK/UTF-8） |
| GeoJSON | 单文件文本 | crs 成员（RFC 7946 后默认 4326，很多工具不再写） | Web 传输、前端直读 | 体积大、精度小数位多 |
| GPKG | 单文件 SQLite | 库内系统表 | 替代 shp 的现代选择，QGIS 默认 | 需要 SQLite 常识 |
| KML/KMZ | XML / zip | 永远 4326 | Google Earth 演示 | 字段能力弱 |
| WKT/WKB | 字符串/二进制 | 不携带 | SQL 里传几何 | 常与 PostGIS 一起用（W7 主场） |
| MVT/PBF | 瓦片二进制 | 瓦片方案定死 3857 | 大数据渲染（W9 主场） | 不可直接编辑 |

**怎么选（决策口诀）**：给人交付 → Shapefile；给网页用 → GeoJSON；自己存档/长期维护 → GPKG。本周三个都会碰一遍。

### 1.2 ogr2ogr 必会参数（用 QGIS 自带的那份，别在 conda 里装 GDAL——W0 笔记 N6 坑）

> **学完你能做什么**：一条命令完成"转格式 + 换坐标系 + 瘦身 + 裁字段"，并且每个参数都能说出在干什么。

先搞清"在哪敲命令"——**OSGeo4W Shell**：

- 【Windows 开始菜单】搜 `OSGeo4W Shell`（装 QGIS 时一起装的），打开是个黑色命令行窗口，里面 `ogr2ogr`、`ogrinfo` 直接能用。
- 【OSGeo4W Shell】验证它活着：

  ```bash
  ogrinfo --version
  ```

  - **预期输出**：`GDAL 3.x.x, released 2025/xx/xx` 之类一行版本号。
  - **失败时**：`'ogrinfo' 不是内部或外部命令` → 你打开的是普通 PowerShell/CMD，不是 OSGeo4W Shell；回开始菜单重新找。

四件套（以 ogrinfo 为例）：

- **定义**：`ogrinfo` = 查看空间数据"身份证"的工具（只看不改）；`ogr2ogr` = 空间数据的"格式转换流水线"（会产出新文件）。
- **类比**：`ogrinfo` 是验货单，`ogr2ogr` 是打包车间——进货（in）→ 按订单要求处理（参数）→ 出货（out）。
- **最小示例**：下面五组命令，每条都能直接跑。
- **常见误区**：① 参数顺序写反——记住口诀 **"选项在前，输出在中，输入在最后"**（`ogr2ogr [选项] 输出文件 输入文件`，和直觉相反，栽过的人极多）；② 在 conda 里另装一套 GDAL 导致两套 GDAL 打架（N6）；③ 路径带中文/空格没加引号（坑 P1）。

【OSGeo4W Shell】五组必会命令：

```bash
# 1) 查元数据（验收项）：坐标系、要素数、字段
ogrinfo -so 输入.shp 图层名

# 2) 转格式 + 重投影 + 精简，一条命令全干
ogr2ogr -f "GeoJSON" -t_srs EPSG:4326 -simplify 0.0005 out.geojson in.shp

# 3) 按属性过滤（只留某些要素）
ogr2ogr -f "GPKG" -where "adcode=440100" out.gpkg in.shp

# 4) 字段裁剪（只留 name、adcode，砍掉其余——减体积利器）
ogr2ogr -f "GeoJSON" -select "name,adcode" out.geojson in.shp

# 5) GPKG 的创建选项（命名图层）
ogr2ogr -f "GPKG" -lco LAYER_NAME=guangzhou_districts out.gpkg in.shp
```

逐参数拆解（第 2 条为例，主计划要你"每个参数都能说清"）：

| 参数 | 大白话 | 写错/漏写的后果 |
| --- | --- | --- |
| `ogr2ogr` | 打包车间开工 | 打成 `ogrinfo`：只看不改，不会生成文件 |
| `-f "GeoJSON"` | 输出格式（format） | 漏了默认输出 Shapefile，想要 JSON 却拿到一堆 .shp |
| `-t_srs EPSG:4326` | **目标**坐标系（target srs），会真的重算坐标 | 漏了就不重投影；和 `-s_srs`（声明源坐标系，不改数值）搞混 = W1 坑 P12 的"改定义 vs 重投影" |
| `-simplify 0.0005` | 简化容差，单位 = **输出坐标系的单位** | 见下方"关键理解"，本周头号暗坑 |
| `out.geojson` | 输出文件 | 和输入写反 → `Unable to open datasource out.geojson`（它去找不存在的"输入"了） |
| `in.shp` | 输入文件（永远在最后） | 路径不对 → 同上报错 |

**关键理解**：`-simplify` 的容差单位是**输出坐标系**的单位。`-t_srs EPSG:4326` 后写 `0.0005` ≈ 55 米容差；忘了 `-t_srs` 而源是 3857 数据时，同样的 0.0005 ≈ 0.5 毫米，等于没简化。**先想单位，再写数字。**

**预期输出**：成功后 ogr2ogr **什么都不打印**（静默成功，Unix 风格），用 `dir out.geojson` 或 `ogrinfo -so out.geojson` 确认产物存在。
**失败时最常见的两条**：`Unable to open datasource`（路径错/中文路径/输入输出写反，坑 P1）；`Failed to create field`（字段名超 10 字符又输出了 shp，换 GeoJSON/GPKG）。

### 1.3 拓扑问题清单（QGIS 检查有效性会见到）

> **学完你能做什么**：拿到"检查有效性"的报告，每条错误你知道它是什么意思、会不会坏事、要不要修。

四件套：

- **定义**：拓扑有效性 = 几何形状有没有违反数学规矩（面不能自相交、环必须闭合等）。
- **类比**：像检查一份合同：自相交 = 签名笔迹穿过自己，法律上无效；未闭合环 = 合同没签字；重复点 = 同一句话写了两遍，不致命但邋遢。
- **最小示例**：【QGIS 界面→`矢量 → 几何工具 → 检查有效性`】跑一遍，看输出图层里 `error` 字段写了什么。
- **常见误区**：① 以为"能显示出来 = 没毛病"——显示从来不检查有效性；② 以为简化只会瘦身——简化**可能制造**新的自相交（练习 3 要亲手验证）；③ 看到"无效"就慌——很多无效几何以显示为目的时无碍，但做分析前必须修。

本周会遇到的五种情况：

- **自相交**（polygon ring 自己交叉）→ 缓冲区分析结果错
- **重复点/钉线**（相邻多边形边界来回走同一条线）→ 面积微偏、共享边不共享
- **未闭合环** → 有的工具直接拒绝读
- **多重面**（一个要素多个环，内环=洞）→ 不算错但容易误解
- **缺 .prj** → 数据"失忆"，W1 三类原因之"类别二"

### 练习 1：下载家乡数据 + 体检（周二）

**为什么做**：一切从"拿到一份来路不明的数据"开始。体检是数据岗的职业习惯——**用之前先看身份证**。

**前置检查**：

- [ ] 能打开浏览器访问 [阿里 DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector)（打不开 → 看 W0 坑 P7，Steam++ 没运行）
- [ ] 开始菜单能搜到 **OSGeo4W Shell**（没有 → 你装的不是 OSGeo4W 版 QGIS，回去补装）
- [ ] 建好工作目录 `D:\xx\GitProjects\gis-learning\projects\data-lab\`（路径全英文，坑 P1）

**步骤 1：下载数据**（浏览器）

- 操作：打开 DataV.GeoAtlas → 左侧搜索你的城市（示例用 `440100` 广州）→ 勾选"包含子区域"→ 点 **下载** → 得到 `440100_full.json`，**剪切**到 `projects\data-lab\`。
- 预期现象：文件 1~5 MB，用 VS Code 打开能看到 `"type": "FeatureCollection"` 开头。
- 失败分支：下载的是 `.json` 但内容只有一层市界（没有区县）→ 回到页面确认勾了"包含子区域"；文件 0 字节 → 重新下载。

**步骤 2：体检**（OSGeo4W Shell）

- 操作：

  ```bash
  cd /d D:\xx\GitProjects\gis-learning\projects\data-lab
  ogrinfo -so -al 440100_full.json
  ```

- 预期现象：刷出一大屏信息。**逐字段解读**（每条都要在输出里找到并抄进笔记）：

  | 输出行 | 长什么样 | 它在说什么 | 异常时 |
  | --- | --- | --- | --- |
  | `INFO: Open of ...` | `using driver 'GeoJSON' successful` | 文件能被识别为 GeoJSON | 打不开 → 文件损坏或路径错 |
  | `Layer name:` | 一般是文件名 | 这"层"叫什么 | — |
  | `Geometry:` | `Polygon` / `Multi Polygon` | 几何类型（区界应是面） | 是 Point → 你下错文件了 |
  | `Feature Count:` | 广州应为 **11**（11 个区） | 要素个数 | 是 1 → 没勾"包含子区域" |
  | `Extent:` | 四个经纬度范围 | 数据覆盖范围 | 数值是几十万上百万 → 是米制坐标，不是 4326 |
  | `Layer SRS WKT:` | 一大段 `GEOGCS[...]` | **坐标系声明**（本周主角，W1 教过看首词） | 没有这段 → 默认 4326，但来源存疑（见步骤 3） |
  | `Geometry Column` | `geometry` | 几何存哪个字段 | — |
  | 字段列表 | `adcode: Integer`、`name: String`、`center: String`… | 每个属性的名字和类型 | 字段名被截断/乱码 → 坑 P2/P3 |

- 失败分支：`Unable to open datasource` → 路径中文/空格（坑 P1）或 `cd` 没成功，先 `dir` 确认文件在眼前。

**步骤 3：⚠️ 本周的 W1 联动实验**（QGIS 界面）

- 操作：把 `440100_full.json` 拖进 QGIS → 叠加天地图底图（W0 已配 key；或用 `XYZ Tiles` 加 OSM）→ 缩放到你熟悉的地标（如广州塔）→ 肉眼检查边界是否整体偏移数百米。
- 预期现象：DataV 数据口径存在 GCJ-02 争议——**可能**看到边界相对底图偏移几百米。
- 失败分支：底图空白 → 天地图 key 的 referer 白名单没加 `127.0.0.1`/`localhost`（W0 §1.4）；看不出偏不偏 → 缩到最大级别再看，几百米在 z=15 以上肉眼明显。
- 收尾：用 W1 练习 3 的方法**自己验证并下结论**（偏移/不偏移、量级多少米），写进 `notes.md`。这比任何教程都有价值。

**完成自查**：

- [ ] `ogrinfo` 输出的七项（层名/几何类型/要素数/Extent/SRS/几何列/字段表）都抄进笔记
- [ ] 要素数与城市实际区县数对得上（广州 = 11）
- [ ] SRS 是 `GEOGCS` 开头（地理坐标系），Extent 数值是经纬度量级（一百多 / 二十多）
- [ ] DataV 坐标系口径的结论已写进 notes.md（附截图）

### 练习 2：瘦身到 100 KB 以内（周三）

**为什么做**：原始文件 1~5 MB，前端加载会卡。瘦身 = 字段裁剪 + 几何简化，两手一起上。

**前置检查**：

- [ ] 练习 1 已完成，`440100_full.json` 体检通过
- [ ] 知道当前数据坐标系（决定 `-simplify` 的单位！）

**步骤 1：先跑一版基准命令**（OSGeo4W Shell）

```bash
ogr2ogr -f "GeoJSON" -t_srs EPSG:4326 -simplify 0.0005 -select "name,adcode,center,centroid" \
  guangzhou_slim.geojson 440100_full.json
```

- 预期现象：静默成功；`dir guangzhou_slim.geojson` 看体积。
- 失败分支：`Unable to open datasource guangzhou_slim.geojson` → 输出/输入顺序写反了（1.2 节口诀）。

**步骤 2：容差试错（按这个流程循环，直到两条都达标）**

```
        ┌──────────────────────────────┐
        │ 跑一次 ogr2ogr（当前容差 T）   │
        └──────────────┬───────────────┘
                       ▼
              文件 < 100 KB 吗？
                │           │
             否 ▼           ▼ 是
        T 翻倍（×2）      QGIS 里叠加原始层目视
        重新跑            形状可接受吗（拐角没塌、
                ▲         邻区之间没裂大嘴）？
                │          │        │
                │        否 ▼        ▼ 是
                │    T 减半（÷2）  ✅ 收工：
                │    重新跑      记录最终 T、体积、
                └────────┘      截图存证据
```

- 容差参考阶梯（4326 下）：`0.0001 ≈ 11 m` → `0.0002 ≈ 22 m` → `0.0005 ≈ 55 m` → `0.001 ≈ 111 m` → `0.002 ≈ 222 m`。从 `0.0005` 起试，形状变形就减小，体积不达标就加大；**每次改容差都重新目视对比**。
- 判断"形状可接受"的粗糙标准：区界拐角没被削成圆弧、相邻区的公共边**仍然贴合**（裂开说明容差太大，或几何本来有钉线）。

**步骤 3：留证据**

- 操作：QGIS 里原始层设红色空心、简化层设蓝色空心，叠加，缩放到一个区的拐角处截图，存 `compare_before_after.png`。
- 验收命令：【OSGeo4W Shell】`ogrinfo -so guangzhou_slim.geojson` 输出正确的 4326 + 要素数（还是 11）。

**完成自查**：

- [ ] `guangzhou_slim.geojson` < 100 KB（`dir` 截图）
- [ ] 要素数没减少（简化不能删区，只能削顶点）
- [ ] 对比截图能看出差异但形状没塌
- [ ] 笔记里写了最终容差 T 和"这个数字在 4326 下等于多少米"
- [ ] 能不看笔记说出：同样 `-simplify 0.0005`，4326 下 ≈ 55 米，3857 下 ≈ 0.5 毫米

### 练习 3：有效性检查与修复（周四）

**为什么做**：上线前的安检。不报错不代表没病——无效几何以"显示"为目的时风平浪静，一做分析就翻车。

**前置检查**：

- [ ] 手里有两份数据：`440100_full.json`（原始）和 `guangzhou_slim.geojson`（简化后）
- [ ] QGIS 已打开，两层都已加载

**步骤 1：检查有效性**（QGIS 界面，逐步路径）

1. 菜单栏 → **矢量(V)** → **几何工具** → **检查有效性…**
2. 弹出对话框，设置三项：
   - `输入图层`：选 `440100_full`（先查原始版）
   - `方法`：选 **`GEOS`**（严格，和 PostGIS 同源；`QGIS` 方法较宽松）
   - `仅检查所选要素`：**不勾**（全查）
3. 点 **运行(R)**，等进度条走完。
4. 预期现象：下方列表列出每条错误（`错误类型` 如 `自相交`，`要素 ID` 指出是哪个区）；地图窗口自动加载一个"错误点"临时图层，红点标出出错位置。**没有错误时列表为空**——空列表也是有效结果，照样截图记录。
5. 失败分支：菜单里找不到"检查有效性" → 你的版本入口可能在 `处理 → 工具箱 → 搜索"检查有效性"`（Check validity），双击算法运行；运行报"层 CRS 无效" → 回 W1 坑表处理坐标系问题。

**步骤 2：对简化后版本再查一遍**

- 操作：同一个对话框，`输入图层` 换 `guangzhou_slim`，再跑一次。
- 预期现象 + 思考点：**对比两份报告**——简化会不会**制造**新的无效几何？（顶点被削后，原本不相交的边可能交叉。这是简化操作的隐藏代价，把它写进笔记。）

**步骤 3：修复**（如果有错误）

- 操作：菜单 → **处理(P)** → **工具箱** → 右侧搜索框输入 `修复几何`（Fix geometries）→ 双击 → 输入图层选出问题的那份 → 运行，得到 `已修复` 新图层 → 右键 `导出 → 另存为` 存成 GeoJSON。
- 预期现象：对修复结果**再跑一次步骤 1**，错误列表应为空。
- 失败分支：修完还有错 → 个别顽固几何（如环方向错误）需手编：右键图层 → `切换编辑状态` → 顶点工具拖动出错点（红标处）→ 保存编辑。

**完成自查**：

### 练习 4：加字段 + 分级 + 上线（周五）

**为什么做**：数据不仅要"能看"，还要"会说话"——加一个业务字段，按它配色，最后放进自己的网页。

**前置检查**：

- [ ] `guangzhou_slim.geojson` 已瘦身且有效性通过
- [ ] `webgis-starter` 能跑（`npm run dev`，W0 练习 1 的肌肉记忆）

**步骤 1：加字段 `district_type`**（QGIS 界面）

1. 右键图层 → `打开属性表` → 左上角 **切换编辑模式**（铅笔图标）。
2. 点 **新建字段**（表格图标带星）→ 名称 `district_type`，类型 `文本(字符串)`，长度 20 → 确定。
3. 点 **打开字段计算器**（算盘图标）→ 勾 `更新现有字段` → 选 `district_type` → 表达式框输入，例如按名称分类：

   ```sql
   CASE
     WHEN "name" LIKE '%区' THEN 'district'
     WHEN "name" LIKE '%市' THEN 'county-level city'
     ELSE 'other'
   END
   ```

   （规则自己定，能讲出逻辑即可；也可以逐行手动填。）
4. 点 **确定** → 属性表里 `district_type` 列有值了 → 点 **保存编辑**（软盘图标）→ 再点铅笔退出编辑模式。
- 预期现象：新列每行都有值。
- 失败分支：字段没存进去 → 忘了点"保存编辑"就关了；表达式报红 → 字段名要双引号、字符串要单引号。

**步骤 2：分类配色**（QGIS 界面）

1. 右键图层 → `属性` → 左侧 **符号化**。
2. 顶部下拉从 `单一符号` 改成 **分类(Categorized)**。
3. `值` 一栏选 `district_type` → 点下方 **分类(Classify)** 按钮。
4. 预期现象：列表里出现每个类别一行（district / county-level city…），地图上的区按类别变不同颜色。
5. 失败分支：分类后全部同色 → `值` 选错字段；颜色太丑 → 点 `符号` 列逐个改，或 `颜色渐变` 下拉换一套。

**步骤 3：拖进 webgis-starter 上线**（浏览器）

1. 【PowerShell】确认服务在跑：

   ```powershell
   cd D:\xx\GitProjects\gis-learning\projects\webgis-starter
   npm run dev
   ```

   - 预期输出：`Local: http://127.0.0.1:5173/`。失败 → 看 W0 坑 P1（是不是用了 pnpm）。
2. 【浏览器】打开 <http://127.0.0.1:5173>。
3. 从资源管理器把 `guangzhou_slim.geojson` **直接拖进地图页面**。
4. 预期现象：地图自动飞到广州（`view.fit` 生效），区界显示在底图上；**点击任意一个区**，弹窗里能看到 `name`、`adcode`、还有你刚加的 `district_type`。
5. 失败分支：
   - 拖进去没反应 → 扩展名不是 `.geojson`/`.json`（坑 P5），先改名；还不行按 F12 看 Console 报错（W0 习惯：先读 stderr）。
   - 显示了但位置飞到海里/非洲 → 坐标系不是 4326，回练习 2 检查 `-t_srs`。
   - 弹窗没有 `district_type` → 你拖的是旧文件（加字段后没另存/没保存编辑），回步骤 1。

**步骤 4：GPKG 留档**（OSGeo4W Shell）

```bash
ogr2ogr -f GPKG guangzhou.gpkg guangzhou_slim.geojson
```

- 预期现象：静默成功，`dir guangzhou.gpkg` 存在。
- 失败分支：`Unable to open` → 顺序反了（输出在前）。

**完成自查**：

- [ ] QGIS 里按 `district_type` 分类配色生效（截图）

### 练习 5（加练，选做）：geopandas 版全流程

**前置检查**：
- [ ] 练习 2 已完成（`440100_full.json` 在手上，本练习直接读它）

**为什么做**：同一件事用 Python 再做一遍，感受"命令行派"和"脚本派"的差别，顺便理解 `preserve_topology`。

【Anaconda Prompt】：

```python
import geopandas as gpd
gdf = gpd.read_file("440100_full.json")
gdf = gdf.to_crs(4326)
gdf["geometry"] = gdf.simplify(0.0005, preserve_topology=True)
gdf = gdf[["name", "adcode", "district_type", "geometry"]]
gdf.to_file("guangzhou_slim_gp.geojson", driver="GeoJSON")
```

对比 ogr2ogr 结果的文件大小与形状差异，思考 `preserve_topology=True` 在防什么（提示：练习 3 你亲手验证过简化会制造无效几何——这个参数就是 GEOS 里"简化时不许造出新的自相交"的开关，代价是瘦身力度略小）。

**完成自查**：

- [ ] 目视两版形状无明显差异；若 geopandas 版更大，能说出这是 `preserve_topology=True` 的代价

## 4. 坑预告（按你的环境定制，遇到就回来打勾）

| # | 预判的坑 | 症状 | 解法 |
| --- | --- | --- | --- |
| P1 | OSGeo4W Shell 里路径带中文/空格 | `Unable to open datasource` | 数据放纯英文路径（如 `D:\gis\`），或整串加引号 |
| P2 | GeoJSON 字段被 ogr 自动改名截断 | 字段名变成 `name_1` 之类 | 正常现象（DBF 10 字符限制的历史），GeoJSON 本身无此限制，转 GPKG 可避免 |
| P3 | DataV 下载的 JSON 里 `type` 字段与 GeoJSON 的 `type` 撞名 | 读属性时困惑 | `-select` 时注意，或 `ogrinfo -so` 先看字段全表 |
| P4 | 简化后面积变了 | 用 4326 直接算面积本来就错（W1 结论） | 算面积先转 CGCS2000 投影带或 `EPSG:4523` 等，或转 3857 之外想清楚再算 |
| P5 | 拖进 webgis-starter 没反应 | 文件扩展名不是 `.geojson`/`.json` | 改名，或看 Console 报错（W0 坑 #2 的习惯：先读 stderr） |
| P6 | raw.githubusercontent.com 拉示例数据失败 | 404/超时 | W0 笔记第六节：Steam++ 的 hosts 加速没开，先启动它 |
| P7 | ogr2ogr 输出/输入写反 | `Unable to open datasource out.geojson` | 口诀："选项在前，输出在中，输入在最后"（见 1.2） |
| P8 | QGIS 里加的字段保存后消失 | 重开属性表新列是空的 | 编辑模式改了字段必须点 **保存编辑**（软盘）再退出铅笔模式；只切出编辑模式会问你"放弃修改吗"，选错就白干 |
| P9 | 简化后相邻区边界裂开缝 | 叠加看公共边不贴合 | 容差太大，减半重跑；或源数据本来有钉线，先修复几何再简化 |
