# WebGIS 12 周学习计划（地理信息科学专业 · 零编程基础版）

> 方向设定：主线 **A = 空间数据服务 + WebGIS 全链路**（就业面最宽，适合打底）。
> 第 13 周起从 **B 三维/数字孪生** 或 **C 遥感 + AI** 里选一条做差异化。
> 行业知识（**D**）不单独占周，穿插在每个阶段的练手题目里。

## 使用说明

- **时间投入**：每天 1.5~2 小时、每周约 12 小时；每周固定三件事：`学 → 练 → 验收`。
- **验收标准必须全部满足才算过关**，不满足就回炉，不要跳周。这是整份计划唯一的纪律。
- **卡住超过 2 小时**：先查官方文档 → 再问 AI → 仍不通就记进"坑表"，先跳过，标注回来补。
- **AI 用法**：让 AI 当助教和实现者（解释代码、生成测试数据、写 SQL、review 你的代码）；
  你负责**跑起来、改一处、说清为什么**。复制粘贴不算学会。
- **每周产出物**：都提交到 Git（GitHub/Gitee 皆可），这最终就是你的作品集。
- **合规习惯**：底图和边界要用标准地图/天地图等合规来源，注意审图号；不要拿高德/百度瓦片直接上线商用。

## 第 0 周 · 环境搭建

**目标**：把工具链装好，能启动项目、能连上数据库。

**学**
- 装：Node.js LTS、Git、VS Code、QGIS、Docker Desktop（需 WSL2）、Python（Miniconda）。
- 读：[webgis-starter/README.md](webgis-starter/README.md)，理解每个文件干什么。

**练**
1. 跑通示例项目：`npm install` → `npm run dev`，打开 <http://127.0.0.1:5173>。
2. 把六个底图逐个点一遍，用 DevTools 的 Network 面板筛选 `png`，观察 `z/x/y` 变化。
3. 用 Docker 起一个 PostGIS：`docker run --name pgis -e POSTGRES_PASSWORD=postgres -p 5432:5432 -d postgis/postgis:16-3.4`。

**验收标准**
- [ ] 页面能打开、底图能切换、示例点线面能显示
- [ ] `psql -h localhost -U postgres -c "SELECT version();"` 能连上
- [ ] 能说出六个底图文件分别在哪个 JS 文件里配置

## 第 1 周 · 坐标系与投影

**目标**：把"图层对不上"这类问题从玄学变成可推理。

**学**
- EPSG:4326 / 3857 / 4490 的定义与使用场景；为什么 Web 墨卡托在高纬会变形。
- GCJ-02（高德、腾讯）、BD-09（百度）偏移的成因与表现。
- `pyproj` 的 `Transformer`，以及 XYZ 瓦片编号公式。

**练**
1. 写一个 Python 脚本：输入经纬度，输出 3857 坐标 + 该点在 z=12/15/18 下的瓦片编号。
2. 在 QGIS 里把同一份数据分别用 4326 和 3857 打开，量同一条线的长度，对比差异并解释。
3. 找一份高德坐标的点和一份 WGS84 的点叠加，量出偏移量，写清结论。

**验收标准**
- [ ] 能手算 z=1、z=2 的瓦片编号，并能解释公式每一项
- [ ] 能说清"同一份数据在 QGIS 里对不上底图"的 3 种可能原因
- [ ] 投影换算脚本能跑，结果和 QGIS 一致（误差 < 1 米）

## 第 2 周 · 空间数据格式与转换

**目标**：能拿到任意格式的数据，清洗成能上线的东西。

**学**
- shp / GeoJSON / GPKG / KML / WKT / WKB / MVT 的差异与适用场景。
- `ogr2ogr` / `ogrinfo` 常用参数：`-t_srs`、`-simplify`、`-where`、`-lco`。
- 拓扑问题：自相交、重复点、无效环、坐标系缺失（.prj 丢失）。

**练**
1. 从 [阿里 DataV.GeoAtlas](https://datav.aliyun.com/portal/school/atlas/area_selector) 下载你家乡的省/市 GeoJSON。
2. 用 `ogr2ogr` 统一成 `EPSG:4326`，用 `-simplify` 把文件压到 100 KB 以内且形状不变形。
3. 在 QGIS 里检查有效性（矢量 → 几何工具 → 检查有效性），修掉无效几何。
4. 加一个字段（如 `name`、`code`），按属性做一次分级。

**验收标准**
- [ ] `ogrinfo -so` 能看到正确的坐标系和要素数
- [ ] 精简后的文件 < 100 KB 且目视形状可接受
- [ ] 把这份 GeoJSON 拖进 `webgis-starter` 页面，能自动定位并显示

## 第 3 周 · Web 与瓦片渲染原理

**目标**：看懂"点一下地图，后台发生了什么"。

**学**
- HTML/CSS/JS 最小必要集：DOM、`fetch`、模块、事件。
- HTTP、CORS、缓存；瓦片金字塔与分级加载；WMS / WMTS / WFS / MVT 的区别。
- 浏览器渲染：为什么地图是"一层层贴图"贴出来的。

**练**
1. 写一个纯 HTML 页面（不用框架）：输入经纬度，用 `fetch` 请求一张瓦片并显示出来。
2. 打开示例项目，在 Network 面板里找到某一级瓦片的请求，记录 z 从 4 到 8 时请求数量的变化规律。
3. 用文字画一遍链路图：浏览器 → 瓦片服务 → 缓存/CDN → 数据源。

**验收标准**
- [ ] 能不用地图库，手写 URL 把指定位置的瓦片显示在页面上
- [ ] 能解释 WTMS 与 WFS 的本质区别（一个给图，一个给数据）
- [ ] 能说出 CORS 报错时该找谁、有哪两种解法

**练**

2. 加一个新功能：**点击要素后侧边栏显示属性表**（不是弹窗），并支持按属性过滤显示。
3. 加一个"图层透明度 + 顺序调整"的面板。
4. 用 `ol/sphere` 自己实现一次测距，验证和项目里结果一致。

**验收标准**
- [ ] 你能从零新建一个图层并加载本地 GeoJSON，不看教程

## 第 5 周 · 可视化与矢量瓦片

**目标**：让地图"会说话"，并理解矢量瓦片。

**学**
- 专题图三件套：分级配色、分类配色、图例；点聚类（`Cluster`）、热力图（`Heatmap`）。
- 矢量瓦片原理（MVT / PBF）、切片与样式的分离（底图样式与数据样式分开维护）。
- MapLibre GL JS 的 `style.json` 结构。

**练**
1. 用同一份数据做 3 张图：分级设色、聚类、热力图，截图存档并说明各自适合什么场景。
2. 用 MapLibre 打开官方示例样式 <https://demotiles.maplibre.org/style.json>，然后用 `setPaintProperty` 改一处配色。
3. 给你第 4 周的图层加一个图例（HTML + CSS 即可），保证能随图层开关联动。

**验收标准**
- [ ] 能说出矢量瓦片相比图片瓦片的 3 个优势
- [ ] 能说出热力图与聚类分别会"骗人"的地方
- [ ] 三张图能在一个页面里切换，图例正确

## 第 7 周 · PostgreSQL + PostGIS

**目标**：数据从"文件"升级到"数据库"，会写空间 SQL。

**学**
- 建库建表、几何类型 `geometry(Point,4326)`、GiST 空间索引、SRID 的意义。
- 10 个必会函数：`ST_AsText`、`ST_GeomFromText`、`ST_Transform`、`ST_Distance`、
  `ST_DWithin`、`ST_Intersects`、`ST_Contains`、`ST_Buffer`、`ST_Area`、`ST_Intersection`。

**练**
1. 用 `ogr2ogr` 或 `shp2pgsql` 把你第 2 周的数据导入 PostGIS。
2. 建空间索引，用 `EXPLAIN ANALYZE` 对比加索引前后的执行计划。
3. 写 5 条有业务意义的查询，例如：
   - 每个行政区内的学校数量并排序；
   - 距离某条地铁线 500 米内的所有小区；
   - 两个图层相交面积大于 1 平方公里的图斑。

**验收标准**
- [ ] 你能解释索引前后 `EXPLAIN` 输出的差异
- [ ] 5 条查询全部写对，且能把结果导出成 GeoJSON
- [ ] 能说清"为什么不能把 4326 的数据直接 `ST_Distance` 当米用"

## 第 8 周 · GeoServer 发布服务

**目标**：把数据库里的数据变成标准 OGC 服务。

**学**
- GeoServer 工作区 / 数据存储 / 图层 / 样式（SLD）、WMS 与 WFS 的差别、坐标系匹配。
- 跨域（CORS）、代理（参考 [vite.config.js](webgis-starter/vite.config.js) 里的 `/geoserver`）。

**练**
1. 用 `docker run -p 8080:8080 docker.osgeo.org/geoserver:2.25.x` 起服务（默认 `admin/geoserver`），连上第 7 周的 PostGIS。
2. 发布 2 个 WMS 图层 + 1 个 WFS 图层，在 QGIS 里先验证能正常加载。
3. 在前端用 `ol/source/TileWMS` 和 `ol/source/Vector`（WFS）各接一次，处理掉跨域。
4. 给其中一个图层写一个自定义 SLD（按属性分级设色）。

**验收标准**
- [ ] 后端改一条数据，前端刷新后能看到变化（说明真的走通了服务）
- [ ] 能说出 WMS 出图与 WFS 传数据的取舍场景
- [ ] 跨域问题是你自己解决的，能讲清过程

## 第 9 周 · 矢量瓦片与性能

**目标**：解决"数据一多就卡死"的实战问题。

**学**
- 切片：tippecanoe（WSL/conda 安装）、`.mbtiles`、缩放级别与简化策略。
- 瓦片服务：`tileserver-gl`、`Martin`、`pg_tileserv`（任选一个跑通即可）。
- 前端渲染优化：分级简化、按需加载、按视野裁剪、`declutter`。

**练**
1. 造 100 万条点数据（脚本随机生成），走一遍 `GeoJSON → tippecanoe → .mbtiles → 前端 MVT` 全链路。
2. 用同一份数据做对比实验：GeoJSON 直载 vs 矢量瓦片，记录首屏时间与拖动帧率。
3. 写一份性能对比记录（表格 + 结论），放进仓库。

**验收标准**
- [ ] 百万级点图层拖动时不明显卡顿
- [ ] 能说出 `--drop-densest-as-needed` 这类参数在干什么、代价是什么
- [ ] 有一份自己测出来的数据，不是抄来的结论

> **阶段二里程碑**：数据库 → 服务 → 前端，闭环跑通。

## 第 10 周 · 空间分析实战

**目标**：从"会画图"升级到"能回答一个业务问题"。

**学**
- 选址分析（多条件打分 + 缓冲区）、可达性（等时圈）、服务区覆盖、适宜性评价。
- 前端轻量分析：`@turf/turf`（缓冲区、相交、最近点）。

**练**
选一个真实小问题（示例，任选其一）：
- 为某区选 3 个社区食堂/快递驿站位置（人口 + 路网 + 已有设施竞争）；
- 统计某条河流 1 公里缓冲区内受影响的地块与人口；
- 分析某市公园 15 分钟步行可达覆盖了多少小区。

要求：数据来源写清、口径写清、结论写清（含局限）。

**验收标准**
- [ ] 有一份 2 页以上的分析报告（问题 → 数据 → 方法 → 结果 → 局限）
- [ ] 所有中间结果可复现（脚本或 SQL 提交进仓库）
- [ ] 能诚实说出你结论的不确定性来自哪里

## 第 11 周 · AI 增强（关键差异化）

**目标**：把 LLM 接进 GIS，同时练"验收 AI"的能力。

**学**
- 大模型 API 调用、结构化输出、Text-to-SQL 的思路与风险（注入、幻觉、坐标口径）。
- 让 LLM 只做"翻译"，真正执行交给数据库；结果必须由人复核。

**练**
1. 做一个小原型：输入自然语言问题（如"找出天河区 1 公里内没有幼儿园的住宅小区"），
   由模型生成 **Spatial SQL** → 后端执行 → 地图高亮结果。
2. 故意给模型设陷阱（字段名不存在、坐标系未指定、问题有歧义），记录它是怎么错的，并加上校验与兜底。
3. 用 AI 生成一份数据字典和接口文档，人工逐条核对修正。

**验收标准**
- [ ] 原型能正确处理 5 个问题，并对 3 个陷阱问题给出合理的拒绝或澄清
- [ ] 你有一段"我怎么防止 AI 胡说"的设计说明
- [ ] 能说出 AI 生成的 SQL 有哪三类必须人工校验的地方

## 第 13 周起 · 差异化延伸（选一条，各约 4~6 周）

### 轨道 B · 三维 / 数字孪生
- **学**：CesiumJS、3D Tiles、倾斜摄影模型、坐标系与地形、WebGL/three.js 基础。
- **练**：把第 12 周的系统加一个三维场景，加载倾斜摄影 + 你的矢量数据叠加；做一次"二三维联动"（点三维模型联动二维定位）。
- **验收**：三维场景帧率可接受、模型与矢量位置对齐、能讲清 LOD 与瓦片调度。
- **适合**：喜欢图形、愿意补数学；单价高但门槛也高。

### 轨道 C · 遥感 + AI
- **学**：Python 数据处理、PyTorch 基础、影像分类/目标检测/变化检测、样本与精度评价（混淆矩阵、IoU）。
- **练**：选一个公开数据集（如 Sentinel-2 / Landsat / 公开标注集），训练一个地物分类或变化检测模型，用第 12 周的系统把结果发布成图层。
- **验收**：有独立的验证集，精度指标可复现，能诚实说明模型在哪些场景失效。
- **适合**：数学不差、想和计算机背景的人正面竞争；天花板高但周期长。

### 加分项 · 行业纵深（D）
不管选哪条轨道，持续做一件事：**选一个行业深挖**（自然资源、水利、应急、交通、电力、农业、双碳），
读它的业务规范与数据标准，把你的项目包装成"解决这个行业某问题"。
这是你区别于计算机转行者的核心壁垒——AI 会写代码，但不会替你去确认"这个图斑算不算违法占地"。

## 学习规则（贴在显示器上）

1. 每周必须有产出物提交到 Git，没有产出 = 这周没过。
2. 官方文档优先于教程，教程优先于二手博客。
3. AI 生成的代码必须跑通 + 改一处 + 能解释，否则删掉重写。
4. 遇到"玄学"问题（对不上、不显示），一定是坐标系、数据或缓存三选一。
5. 卡住 2 小时先记坑表跳过，不要在一处耗掉一整周。
6. 每 3 周回看一次自己的旧代码，能当场指出 3 个可以改进的地方，说明你在进步。
